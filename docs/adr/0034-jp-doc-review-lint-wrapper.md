# jp-doc-reviewerのリンターを、HTMLをテキストに直すラッパー経由で呼ぶ

## 背景

2026-10-13、業務リポジトリのセッションでConfluenceへHTMLを投稿した。フックが書き出した下書き（約24KB・1行のHTML）に
jp-doc-reviewerがyomiyasuのリンターをかけると、結果は「文字数0・行数0」でPASSだった。同じセッションで3回、同じ結果になった。

リンター（submoduleの `skills/yomiyasu`、上流はサードパーティ）は、`<` で始まる行を地の文から外す。
「手触り」を含む1文で比べると、`.md` では文字数25で警告が出て、`<p>…</p>` で囲んだ `.html` では文字数0でPASSになった。
リンターは文字数0でも終了コード0を返すので、「検査できなかった」と「問題なし」を区別できない。

レビュワーは下書きをその場で直し、その後にリンターで確かめる。レビュワーのBashは、
フック（`pre-tool-use-reviewer-bash`）がリンターの呼び出しだけに絞っている。

## 決定

1. 自前のラッパー `hooks/jp-doc-lint.py` を置く。呼ばれるたびに現在のファイルを読み、拡張子が `.html` ならテキストに直してから、
   yomiyasuのリンターを `--json` で呼ぶ。写しのファイルは作らない
2. リンターが数えた文字数が0のとき、リンターが失敗したとき、出力を読めなかったときは、終了コード2で「検査できなかった」と出す。
   HTMLに限らず、Markdownでも同じに扱う
3. レビュワーのBashで許すのは、ラッパーだけにする。yomiyasu_lint.py の直接呼び出しは止める。
   ラッパーは実体で比べ、相対パスは通さない。対象のファイルは、シングルクォートで囲んだものか、
   英数字と `_./-` だけのものを通す。security-reviewerの指摘で、禁止文字を並べる形をやめた。
   その形では、zshのグロブ修飾子 `(e:...:)` や `$HOME` を通していた
4. `<` で始まる行が一部だけあるMarkdownは止めない。止めると、`<details>` などHTMLを含む正当なMarkdownが毎回止まる。
   その場合、一部の行が検査されないまま、残りの行でPASSになる。これを受け入れることは、2026-10-13にユーザーが決めた

## 検討した代替案

### 下書きを書き出すときに、テキスト版も書き出す（却下）

変更はフックの1か所で済む。しかしテキスト版は書き出した時点の写しで、レビュワーが `.html` を直した後にリンターをかけると、
直す前の本文を検査する。直した結果を一度も検査しないまま「検査済み」に見えるので、今回の穴を別の形で作り直すことになる。

### 上流のリンターにHTML対応を足す（却下）

修正が一番根本に近い。しかし上流はサードパーティで、取り込まれる時期をこちらで決められない。
取り込まれても、0文字でPASSを返す挙動は上流の判断になり、こちらで「検査できなかった」として扱える保証が無い。
上流への報告は妨げない。HTML対応が入ったら、ラッパーの変換を外せるかを見直す。

### yomiyasu_lint.py の直接呼び出しも許したまま、ラッパーを足す（却下）

レビュワーが直接呼べば、HTMLで0文字のPASSがまた出る。どちらを呼ぶかをエージェントの指示だけに任せることになる。

ラッパーを呼ぶかどうかも、エージェントの指示に任せている点は同じである。違いは、指示に従ってリンターを呼んだときに出る結果にある。
直接呼び出しを残すと、呼んでも誤った「問題なし」が出うる。ラッパーだけにすれば、呼べば正しい結果か「検査できなかった」が出る。
呼ばなかった場合を検出する仕組みは、この決定に含めない（backlogで扱う）。

## 結果

- HTMLの下書きの日本語が、リンターで検査される。1行のHTMLも、ブロック要素ごとに行を分けてから渡す
- リンターの指摘の行番号は、変換後のテキストの行で、下書きの行とは一致しない。ラッパーはそのことを出力に書く。
  元の行へ戻す処理は入れなかった。フックが書き出すConfluenceの下書きは1行のHTMLになることがあり、そのときは戻しても行が1つしかない。
  指摘には該当する文の引用が付くので、レビュワーはその文で下書きの場所を探せる
- ADFの下書き（`.json`）は変換しない。JSONの行は地の文として数えられるので文字数0にはならないが、JSONの記号も文字に数えられる
- `<` で始まる行が一部だけあるMarkdownでは、その行は検査されないまま、残りの行でPASSになりうる（決定4）
- レビュワーがラッパーを実際に呼んだかは確かめない
