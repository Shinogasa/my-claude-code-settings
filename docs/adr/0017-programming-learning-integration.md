# 本人による実課題の完遂と専用リポジトリへの学習記録集約

## 背景

ADR 0001・0007の設計判断学習と、ADR 0012のコード技能学習は異なる能力を扱う。
初期のコード学習は小問への回答を優先し、本人が調査・変更・検証の次の行動を選ぶまでの担当拡大が弱かった。
公開の専用学習repoへの集約を含む設計を見直し、ユーザーは2026-09-22に
「所要時間より、一度決めた課題を自力でやり切ることを優先」と指定した。
改訂案とモデル分担の提示後、実装計画への移行を依頼した。本ADRはこの設計承認を記録する。
拡張実装と実ホストの対話検証、実ユーザーの成長の観測はまだ行っていない。

## 決定

1. **共通規則を既存learning-modeへ集約する。** ON/OFF、イベント上限、候補の担当、開示順、保存先確認を
   共通節で所有する。判断基準の3軸とコード行動の評価は分け、二層構成を維持する。
   「複数案を提示したら必ず発火」は適格条件と上限による選別へ置き換える。
2. **対象能力と支援量から形式と担当範囲を選ぶ。** Writeの固定優先をやめ、Investigateを追加する。
   一工程の成功から小さな実課題の一連の作業へ担当を広げ、通常作業での自発的な行動も証拠にする。
   公式資料・検索・debuggerを使用でき、資料を使わない暗記を自立性とみなさない。
3. **本人が担当範囲を完了するまで支援する。** 行動と理由は順に取得し、誤解には反例や観測差を返す。
   再試行回数・時間だけでAIへ引き取らず、停滞時は前提を補うか範囲を調整する。
   理由回答だけでは完成解を開示しない。本人の中断・skip・引取り希望と必要な安全介入を認める。
4. **実証できた範囲だけを記録する。** 支援付きの完遂、独立成功、自発的な開始を分け、
   提示済みの箇所・仮説・テストと比較条件を残す。AI作成テストの成功を本人の検証設計の証拠にしない。
   即時転移、後日の保持、教育効果の因果関係を分け、正答率から成長や易しすぎる出題を断定しない。
5. **新規記録の正本をPUBLICの専用学習repoへ移す。** 共有ルールに個人の保存パスを埋め込まず、
   ローカルbindingとstore IDで識別する。CLIは保存・検査だけを担当し、教育判断・ネットワーク操作をしない。
   保存失敗は未保存と明示し、作業repoへの暗黙fallbackを行わない。teach・常駐hook・DBは追加しない。
6. **訂正と旧記録の移管は履歴を保つ。** event IDとrecord IDを分け、supersedesのUUID配列で訂正を表す。
   通常は唯一の末尾を、分岐解消は全末尾を明示して新版へ置換する。旧記録は本文不変のlegacyとして照合し、
   新しい能力証拠へ自動変換しない。公開前の抽象化確認は本文・名前・取込metadataにも適用する。

ADR 0001の自己生成・理由取得、ADR 0007の設計判断の層ゲート、ADR 0012の役割分離と外部検証は維持する。
本ADRは固定Write優先、共通規則の重複、旧保存先、上記と衝突する発火・正答率の解釈を部分的に置き換える。
旧ADRの本文は当時の判断として残す。運用値と詳細契約の正本は承認済み設計書とする。

## 検討した代替案

- **短い小問と再試行1回を維持する**: 時間を見積もりやすいが、本人による完遂を優先する希望に合わない。
- **毎回タスク全体を無支援で任せる**: 広い能力を観測できるが、未確認の前提を同時に要求する。
  観測できた能力から担当を広げる方針を採る。
- **学習モードを同じ採点形式へ統合する**: 入口は減るが、判断基準とコード行動の証拠を混同する。
- **teachへ記録機能ごと依存する**: ユーザーが今回の導入を見送った。実務内学習と記録集約を独立して成立させる。
- **両repoへ同期、または保存失敗時に元repoへ戻す**: 環境によって正本が変わり、静かな欠落を再発させる。
- **訂正分岐を自動的に採点して統合する**: 根拠の異なる評価のどちらを残すかをCLIが決めてしまう。
  全末尾を明示した訂正で履歴を保持し、判断できない部分は未確認として残す。

## 結果

AIが準備した部分問題から、本人が必要な行動を選んで完了する練習へ移る契約ができる。
一方で対話は長くなり得る。待機中にAIが本人の担当を完成させず、支援の変更や中断を扱う必要がある。
専用repoのbinding・移管・訂正履歴も運用対象になるため、保存可否・commit・remote反映を別に報告する。

静的テストはルールの契約を、保存CLIのテストはデータ操作を検証する。
実ホストの複数ターンの動作と、5〜10件の適格な実作業でのpilotは別に検証する。
少数pilotや即時の正答を、長期の成長や教師の誤採点率の保証にしない。
