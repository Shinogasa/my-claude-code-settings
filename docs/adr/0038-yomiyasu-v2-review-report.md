# yomiyasu v2をsymlinkで配り、差分の検査をラッパー経由で記録なしに使う

## 背景

主な問題は、yomiyasuを最新へ追従させるとv2の構成の変更で日本語レビューが黙って止まることだった。
v2へ上げたのは、上げないと困るからではなく、最新に追従したほうが推敲の質が上がっているはずだから（ユーザーの判断）。
対応の途中で、直した内容を追えないという2つ目の問題が加わった。決定1〜3はおもに1つ目、決定4〜7はおもに2つ目に答える。

yomiyasuのsubmoduleをv1.0.1+1からv2.1.2へ上げた。v2では上流がリポジトリの構成を変え、スキル本体が
`skills/yomiyasu/` の下へ移って、ルートの `SKILL.md` が無くなった。そのまま上げると、日本語レビューのフックは
`~/.claude/skills/yomiyasu/SKILL.md` を見つけられず、レビューを省略して先へ進む。

v2では、原文と最終稿を機械で比べる検査スクリプト `yomiyasu_check.py` も入った。一方、これまでのレビュワーの報告は
「変えた点（短く）」だけで、ユーザーは、何をどう直したかを会話から追えなかった。

設計は `docs/superpowers/specs/2026-10-22-yomiyasu-v2-design.md`、計画は `docs/superpowers/plans/2026-10-22-yomiyasu-v2.md`。

## 決定

1. submoduleを `vendor/yomiyasu` へ移し、`skills/yomiyasu` をスキル本体 `../vendor/yomiyasu/skills/yomiyasu` へのsymlinkにする（ADR 0035と同じ形。ユーザーの判断）
2. リンターの探し先と必読資料の置き場は、スキル本体だけにする。v2のsubmoduleのルートにも古い版のリンターと資料が残るので、
   本体とは別の版を黙って使わないため（設計者の判断）
3. submoduleのルート（`vendor/yomiyasu`）も、レビュワーのEditから守る。スキル本体の外にある古い版のスクリプトを書き換えさせないため（設計者の判断）
4. 差分の検査は `yomiyasu_check.py run --no-record` だけを使い、`verify` は使わない（ユーザーの判断）。
   代わりに、レビュワーの手順を「最後のラッパーの後はEditしない」にする
5. 検査はレビュワーに直接打たせず、今あるラッパー `hooks/jp-doc-lint.py` の中から呼ぶ（ユーザーの判断）。
   レビュワーのBashは、今と同じラッパー1本の形のまま
6. 原文は、レビュワーを起動するときにフックが `~/.claude/state/jp-doc-review/sources/<セッション>/` へ写す（0700/0600）。
   レビュワーの定義の `Stop`（SubagentStopに変わる）で消し、落ちて残ったものは7日の保存日数で消す。検査は、この置き場の下の一時ディレクトリで動かす。
   置き場と消し方は設計者の判断（業務repoの中には置かない、はユーザーの判断）
7. レビュワーのBashのフックは、決まった形のラッパーのコマンドに `--session <キー>` を `updatedInput` で足し、`allow` で通す（ユーザーの判断）。
   ラッパーは、そのセッションの写しだけを使う。レビュワー自身が `--session` を書いた形は拒否する
8. レビュワーは、意味が変わりうる直しなどの重要なものだけを `元の表現 → 直した表現（理由）` の対で、レビュー全体から返す。
   メインのエージェントは、それを要約せずにユーザーへ見せる（フックの止める理由に書く）。
   重要なものだけを対で見せることと、件数の上限を設けないことはユーザーの判断。対の形をv2の「変えたところ」欄に合わせたのは設計者の判断

## 却下した案

### `setup.sh` でyomiyasuだけリンク元を入れ子に変える

submoduleを動かさずに済む。だが、`skills/yomiyasu` の中身と配る中身が食い違ったまま残り、`setup.sh` のClaude側とCodex側の両方に例外が入る。
上流がまた構成を変えたときも、symlinkなら1本を張り替えるだけで済む。

### 作業repoに検査の記録を残す

`verify` の照合が使える。だが、業務repoの `.yomiyasu/` に原文と最終稿の全文の写しが溜まる（gitには乗らない）。

### 記録を作業repoの外の一時フォルダに残し、レビューの終わりにフックで消す

`verify` も使えて、業務repoには何も残らない。だが、`verify` が守るのは「検査の後に書き換えない」ことだけで、
手順の決まりで足りる。守れるものが小さい割にフックの手間が増える。

手順の決まりで守る代わりに、利用者に負担が1つ残る。レビュワーが手順を破って検査の後に直すと、報告の対と最終稿がずれ、
それに気づく仕組みは無い。ずれるのは報告の対の正確さだけで、最終稿そのものは、メインのセッションで差分（`git diff` など）を見れば確かめられる。

### 検査スクリプトを使わず、リンターだけを呼ぶ

意味がずれた直し（伝聞を断定にする、許可の言い方を消すなど）を機械で拾えず、報告の対を選ぶ根拠も無い。

### レビュワーに `yomiyasu_check.py` を直接許可する

フックが、写しのパスがそのセッションのものか、`--final` が依頼されたファイルか、`--state-dir` や `--material` のような余計なオプションが無いかを
すべて検査することになる。HTMLの下書きはテキストに直さずに比べることになり、`--no-record` の付け忘れも防げない。

### 全セッションのうち最新の写しを使う

フックを書き換えずに済む。だが、同じファイルを2つのセッションが同時にレビューすると、片方が別のセッションの写しと比べ、
食い違いに気づく手間をユーザーが負う（原則レビューの指摘）。

## 結果

- 直した内容を追えるようになったかは、実機で一度レビューを起こし、報告に `元 → 後` の対が出るかで確かめる。
  2026-10-22に、新しいプロセス（`claude-headless -p`）からv2のレビュワーを起動し、対が4か所出ること、
  写しの置き場が終わったあと空になること、作業ディレクトリに `.yomiyasu/` が無いことを確かめた。
  このときレビュワーは「意味が変わりうる直しは無い」と書いたうえで、軽い直しも並べた（指示より多めに出す）。
  報告の節に「重要な直しが無ければ対を1つも書かない」「検査の『実行しなかった検査』の案内は書かない」を足して2回目を確かめたところ、
  対は意味に関わる2件だけになり、軽い直しは種類ごとに1行でまとめられた（所要時間は90秒）
- v1と同じ文書（ADR 0035の写し）で、レビュー1回の所要時間を比べる（v1はサブエージェントだけで55.3秒、v2は `claude -p` の起動を含む全体で71秒）。
  2倍を超えたら、必読資料と検査の足し方を見直す
- v2の `SKILL.md` は約113KBで、v1の約13KBより大きい。レビュワーは全文を読むので、読む量は増える
- リンターの `--json` の `score` は v2 で `rule_penalty_score` に改名された。ラッパーは新しい名前だけを読む
- フックが `allow` を返すので、決まった3語の形のラッパーのコマンドは、利用者の確認なしで通る

### 見直す条件

- 1回の報告で対が10組を超えたら、上限を決め直す（`tasks/backlog.md`）
- 上流がまた構成を変えたら、symlinkの先を張り替える
- 同じセッションで並行するレビュワーは、写しのディレクトリの `.active`（動いている数）で数え、最後の1つが終わったときに写しを消す
- `updatedInput` がサブエージェントの定義のフックで効かなくなったら、ラッパーはセッションを受け取れず、差分の検査は「実行できなかった」になる

## 根拠

- 2026-10-22に `claude -p` で、プロジェクトのエージェント定義のPreToolUse(Bash)のフックが返した `updatedInput` が効くことを確かめた（`echo a` が `b` を返した）
- `yomiyasu_check.py run --no-record` を一時ディレクトリで実行すると、そのディレクトリに `.yomiyasu/` を作らず、
  「直した箇所（元と後）」と「文の種類の印が変わった文」の節を出す（2026-10-22に確認）
