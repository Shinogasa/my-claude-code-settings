# ペルソナと原作との照合結果を `docs/research/` に残し、違和感が出たら読み直して追記する

## 背景

目的は、ペルソナの応答が原作から外れたとき、原作を一から読み直さずに根拠を確かめて直せるようにすることである。

伊集院北斗のペルソナ（`personas/*.md`）は、2026-10-16に原作の台詞集を読んで作った（PR #96・#97）。
2026-11-03、あるセッションの最初の応答が「チャオ☆ 北斗だよ。」になった。ユーザーが違和感を持ち、原作を読み直すと、
「チャオ☆」は原作にあるが、名乗る台詞は1つも無かった。

作成時の分析は、ペルソナに書いたおおよその件数とPR本文の要約しか残っていなかった。
台詞の一覧も、数え方も、「原作に無いこと」も記録していない。そのため、違和感が出るたびに
原作を最初から読み直すことになり、今回の照合結果も残す場所が無かった。

## 決定

1. 原作との照合結果を、`docs/research/persona-<キャラクター>-source.md` に残す。北斗は `persona-hokuto-source.md`
2. 書くのは、出典のURLと取得日、読んだ範囲と読んでいない範囲、件数・出現位置、判定に必要な短い引用、
   原作に**無い**と確かめたこと（その範囲と反証条件も）。台詞の全文は転載しない
3. ユーザーが応答に違和感を持ったら、次の順で進める
   1. 記録に同じ点の照合が既にあるかを見る。あれば、それに従ってペルソナを直す
   2. 無ければ原作を読み直し、結果を日付つきで記録の末尾に追記する
   3. `personas/` の両版を直し、`persona <名前>` で `rules/persona.md` へ書き写す（ADR 0037）
4. ペルソナの指示から、根拠になった照合記録を参照する

誰が決めたか（2026-11-03、作業の会話の中で）:

| 決定 | 決めた人 | 経路 |
|---|---|---|
| 照合結果を残すこと、違和感が出たら読み直すこと | ユーザー | ユーザーが会話で提案した |
| 1・2（置き場所、全文は転載しない） | AIが提案し、ユーザーが承認 | 完了条件の確認（AskUserQuestion）で、この2点を含む案に「これでいい」と答えた |
| 3の細かい手順、4 | AI | PRのレビューで、ユーザーが覆せる |

## 検討した代替案

### 台詞の全文をリポジトリに保存する

採らなかった。リポジトリは公開されており、ゲームの台詞をまとめて転載することになる。
件数・位置・短い引用があれば、判定の根拠としては足りる。全文が要るときは出典を読み直す。

### 記録を残さず、違和感が出るたびに原作を読み直す

採らなかった。今回がこの方法で、作成時の分析を確かめられなかった。読み直す範囲や数え方も毎回ぶれる。
「原作に無い」と確かめた結果も、次に同じ違和感が出たときに使えない。

### 照合結果を学習store・永続メモリなど、リポジトリの外に置く

採らなかった。ペルソナ本体（`personas/`）と別の場所に置くと、ペルソナを直す人が根拠を見つけられない。
永続メモリは作業ディレクトリごとに分かれ、Codex CLIからも読めない。

### ペルソナ全体を定期的に原作と照合する

採らなかった。理由は作る側の手間で、使う側の事情ではない。
原作には数十枚のカードの台詞があり、全体を読み直すたびに大きな手間とトークンがかかる。
また作成時の件数は数え方が残っておらず、比べる基準が無いので、定期的に読み直しても差分を出せない。
その代わり、**ずれを見つける負担はユーザーに残る**。違和感が出るたびに記録が増えれば、
同じずれは二度目から記録で確かめられる。違和感の頻度が上がったら、この判断を見直す。

## 結果

- 違和感が出たとき、まず記録を見れば、照合済みかどうかが分かる
- 原作に無いことを記録するので、モデルが補いがちな振る舞い（名乗りなど）を、根拠つきで禁止できる
- 作成時の分析（2026-10-16）は再現できない。件数は数え方が残っていないので、検証できない値として扱う
- 記録を更新するのは、違和感が出たときだけ。ずれに気づくのはユーザーに頼っている
- ペルソナに原作の例文を入れるかどうかは、このADRでは決めない（`tasks/backlog.md` に積んだ）

## 根拠

- `docs/research/persona-hokuto-source.md`（2026-11-03の照合と、他の人のペルソナの作り方の調査）
- ADR 0037（`personas/` から `rules/persona.md` へ書き写す仕組み）
