# origin/main に取り込まれていないローカルブランチの削除を、フックで止める

## 背景

目的は、AI がブランチを片付けるとき、`origin/main` にまだ取り込まれていないローカルブランチを消すのを、実行前に止めることである。

2026-11-03、別のリポジトリ（Hugo のブログ）の後片付けで、AI がまだマージしていない PR のローカルブランチを
`git branch -d` で消した。

- 消したブランチは push 済みで、upstream（`origin/<同名>`）が設定されていた
- `git branch -d` は、upstream があれば upstream に、無ければ HEAD に取り込まれていれば消せる。
  そのため、main に未マージでも upstream と同じなら通る
- AI は「`-d` はマージ済みしか消せないから安全」と思い違いをしていて、PR の状態を確かめていなかった
- リモートに同じコミットが残っていたので、すぐ戻せた。被害は無かった

再発防止の方式は、利用者との議論で「フックで止める」に決まった。
今回のミスは決まりが無かったからではなく、コマンドの仕様を思い違いしていたから起きた。
思い違いをしている間は、手順の決まりを読んでも「安全な操作」と判断して通してしまう。
フックなら、思い違いがあっても実行前に止まる。

## 決定

1. `hooks/guard-dangerous-bash.py` に判定を足す。`git branch` の削除（`-d` / `-D` / `--delete`、
   まとめ書きの `-df`、略記の `--del` を含む）と `git update-ref -d refs/heads/<name>` で、
   対象が `origin/main`（無ければ `origin/master`）の祖先でなければ止める。判定は
   `git merge-base --is-ancestor` の終了コードで行う。複数のブランチを並べた場合は、1つでも該当すれば止める
2. 判定できないときも止める（fail-close）。対象のリポジトリを特定できない（`cd "$X"` など）、
   `origin/main` も `origin/master` も無い、ブランチ名を解決できない、`merge-base` が 0/1 以外で終わる、
   git が `GIT_TIMEOUT_SEC`（3秒）以内に終わらない、の5つ
3. フックの中では fetch しない。ローカルの `origin/main` が古いとマージ済みでも止まるので、
   メッセージで `git fetch --prune` と `gh pr view <branch> --json state` を案内する
4. squash / rebase マージの例外は設けない。そうしたブランチは祖先にならないので止まる。消すなら利用者が端末で実行する
5. `-r` / `--remotes`（リモート追跡ブランチの削除）は対象外にする。fetch で戻せるため
6. `git branch --delete-merged`（git 2.56 で入った）は、`--dry-run` を付けたもの以外を止める。
   これも upstream に取り込まれていれば消すので、`-d` と同じ穴がある。消す対象は git が実行時にパターンから決めるため、
   フックでは列挙できない。メッセージでは、dry-run で確かめてから `-d` で1つずつ消すよう案内する

誰が決めたか（2026-11-03、作業の会話の中で）:

| 決定 | 決めた人 | 経路 |
|---|---|---|
| フックで止める方式 | 利用者 | 依頼の前の議論 |
| 1・2・4・5 | 利用者 | AI が完了条件の案として出し、承認を得た |
| 3 fetch しない | 利用者 | 学習モードの予測では「毎回先に fetch」を選んだ。AI が下の理由で採らない案を開示し、その後、利用者が承認した |
| 4 の前提（すべて merge commit で取り込んでいる） | 利用者 | 原則レビューの問いを受けて、AI が確かめていないと伝え、利用者が「squash マージのリポジトリは無い」と答えた |
| 6 `--delete-merged` を止める | 利用者 | 実装中に AI が `git help branch` で見つけて足した。原則レビューの問いを受けて、完了条件の変更として承認を得た |

## 検討した代替案

### 手順の決まりを足す（「消す前に PR の状態を確かめる」）

採らない。思い違いをしている AI は、その操作を確かめる必要のある操作だと認識しない。決まりを読んでも適用しない。

### AI にブランチを削除させない

採らない。マージ済みのブランチの片付けは日常の作業で、すべて止めると利用者の手間が増える。
手間が増えると、フックごと外される方向へ倒れる。

### upstream で判定する（git 自身の `-d` と同じ基準）

採らない。今回すり抜けたのがまさにこの基準である。

### 判定の前に毎回 fetch する

採らない。PreToolUse フックは実行前に同期で走る。fetch はネットワークと認証に依存するので、
認証待ち（パスフレーズ付きの SSH 鍵で agent が無いなど）、オフライン、ネットワークを許さないサンドボックスでは
3秒に収まらず、fail-close で毎回止まる。マージ済みのブランチも消せなくなる。
タイムアウトを延ばせば、すべての削除が遅くなる。また、判定のついでに remote-tracking ref を書き換える
（`fetch.prune` が有効なら ref を消す）。ガードは状態を読むだけにしておく。

### 未マージと判定したときだけ fetch して判定し直す

採らない。fetch が必要になるのは判定が分かれる場面で、そこで上と同じ失敗の仕方が出る。
AI が自分で `git fetch` してやり直せば、同じことを出力の見える形でできる。

### upstream が `[gone]` のブランチは通す（squash マージへの対応）

採らない。PR を閉じてリモートを消した未マージのブランチも gone になり、通ってしまう。
利用者のリポジトリはすべて merge commit で取り込んでいる（2026-11-03 に利用者が確認）ので、今は困らない。
squash / rebase マージのリポジトリを使い始めて、マージ済みのブランチが止まるようになったら見直す。

### `gh pr view --json state` が MERGED なら通す

採らない。PR の状態は GitHub に問い合わせないと分からないので、fetch と同じく同期経路にネットワークと認証の待ちが入る。
GitHub 以外のリモートや、PR を通さずに push したブランチでは判定できない。また、PR がマージされた後に
同じブランチへ足したコミットも、MERGED と出て通ってしまう。メッセージで確かめ方として案内するにとどめる。

## 結果

- push 済みの未マージブランチを `-d` で消す経路が止まる。リモートを先に消して upstream を gone にしてからの `-d` も、
  upstream を見ないので止まる
- 失うもの: ローカルの `origin/main` が古いとき、squash / rebase マージのリポジトリでは、マージ済みでも止まる。
  前者は fetch で直り、後者は利用者が端末で実行する
- 既知のすり抜け（backlog に積んだ）: `rm .git/refs/heads/<name>` や packed-refs の直接編集、
  `git update-ref --stdin` の delete、`git push . :refs/heads/<name>`、`--git-dir` / `--work-tree` との組み合わせ、
  git alias、`git branch -M` / `-f`・`git checkout -B`・`git switch -C` による上書き、`xargs` や `bash -c` の中の git
- `git branch` が消せる経路は、git 2.56 の synopsis で `-d|-D` と `--delete-merged` の2つだと確かめた。
  git の他のサブコマンドやファイル操作で消せる経路は、上の列挙以外を網羅したとは確かめていない
- 値を取る `git branch` のオプション（`--format` など）は読み飛ばさない。値をブランチ名と取り違えると、
  解決できずに止まる側へ倒れる
- このフックは Codex CLI からも `codex/hooks.json` 経由で呼ばれる。追加した判定は Claude Code 固有の前提を持たない

## 根拠

- `git help branch`（`-d`: "The branch must be fully merged in its upstream branch, or in HEAD if no upstream was set with --track or --set-upstream-to."）
- `git help merge-base`（`--is-ancestor`: 祖先なら 0、そうでなければ 1、エラーはそれ以外で終わる）
- ADR 0043（secret の読み取りガード）、ADR 0044（セキュリティ指摘の仕分け）
