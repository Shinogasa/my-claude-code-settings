# テンプレートから消したキーを、前回の記録との3-wayで settings.json から消す

## 背景

`setup.sh` は、既存の `~/.claude/settings.json` を読み、その上に `settings.json.template` を重ねて書き出す。
`permissions` はリストに規則を足すだけにしている。既存の内容を残すのは、Claude Code自身や利用者が
`settings.json` に書き込むためである（`/effort` の `modelSettings`、`/auto-mode-setup` の `autoMode` など）。

この作りでは、テンプレートからキーを消しても、動いている設定から消えない。PR #117 でテンプレートから
`effortLevel: xhigh` を消したが、`setup.sh` を実行した後も残っていて、手で消した。
`ownership.json` が記録していたのは生成したファイルのハッシュだけで、前回テンプレートが何を書いたかは
分からなかった。

## 決定

- `ownership.json` に、前回適用したテンプレートを `templates`（生成先のパスごと）として残す
- 前回のテンプレートにあって今回無いキーは、動いている値が前回の値のままなら消す。
  値が変わっていれば、誰かが決めた値として残し、標準エラーに知らせる
- `permissions` の `allow` は、テンプレートから消した規則だけを取り除く。利用者が足した規則は残す
- `deny` と `ask` は、テンプレートから消した規則も自動では消さず、標準エラーで知らせる。
  消すと守りが緩むうえ、利用者が同じ規則を自分で足していた場合と区別できないため（自動セキュリティレビューの指摘）
- 消すと守りが外れる設定（`hooks`・`enabledPlugins`・`sandbox`・`disableAllHooks`・`allowManagedHooksOnly`、
  `permissions` の `defaultMode`・`disableBypassPermissionsMode`）も、値が同じでも自動では消さずに知らせる（security-reviewerの指摘）
- 実際に消したキーも、標準エラーに1行ずつ出す。間違って消したときに気づけるようにする
- 適用のたびに今回のテンプレートを基準として記録し直すので、残したキーの通知は次の1回だけで止まる
- 記録が無いとき（この変更の後の初回）は、何も消さない

## 検討した代替案

### 消すキーの一覧をテンプレートに書く

記録が要らず、何を消すかが差分で読める。しかし、消すときに一覧へ書き足すのを忘れると、今回と同じ取り残しが
黙って起きる。一覧も消したキーの分だけ増え続ける。

### 消さずに警告だけ出す

人の決めた値を消してしまう危険は無い。しかし、「前回あって今回無い」を判定するには、この決定と同じ記録が要る。
それでいて、毎回手で消す作業が残る。

### 毎回テンプレートで丸ごと置き換える

Claude Codeが `settings.json` に書き込む値（`modelSettings` など）が、`setup.sh` を実行するたびに消える。
書き込み先を別のファイルに移す手段も無いので採らない。

### `deny`・`ask` もほかと同じく自動で消す

実装はそろう。しかし、テンプレートが足す前から利用者が同じ規則を持っていた場合、記録からは区別できず、
利用者の規則まで黙って消える。消したときに守りが緩む向きなので、人が決める。

### 前回の値と比べずに消す

実装は最も短い。しかし、テンプレートが持っていたキーを利用者が後から書き換えていた場合、その値まで黙って消える。

## 結果

- テンプレートからキーを消せば、次の `setup.sh` で動いている設定からも消える
- この変更より前に消したキーは、記録が無いので消えない。`effortLevel` は手で消し済み
- `env.json.template` から消した環境変数のキーは、今回の対象外で、まだ残る
- `ownership.json` を書き換えられれば、消すキーを指定できる。ただし守りのキーは消せない。
  また、`ownership.json` を書き換えられる人は `settings.json` も直接書き換えられるので、
  記録をテンプレートのハッシュに結び付ける対策は採らなかった
