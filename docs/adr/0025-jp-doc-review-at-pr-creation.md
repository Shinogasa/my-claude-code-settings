# 日本語文書のレビューの時機をPR作成時に移す

## 背景

ADR 0024の決定1では、Write・Editの後に書き込みを記録し、`git commit` の直前に1回だけ止めてレビューを依頼していた。
運用を始めてから、backlogに次の課題が積み上がった。

- Write・Editを通らない書き込みは記録されない。2026-10-02に、実装を頼んだサブエージェントが設計書とADRを
  Bashから動かしたPythonで書き換え、どちらもレビューの対象に入らなかった
- コミットの見分けに取りこぼしと取り違えがある。`bash -c "git commit ..."` や `env A=b git commit` を見分けず、
  `cd <別のリポジトリ> && git commit` ではコミット先を取り違える。記録がセッションごとにあるので、
  リポジトリXで止めた後にリポジトリYでコミットすると、Yのコミットが2回目として通る
- 包んだ形を追うほど、判定のコードが大きくなる

2026-10-03に、ユーザーから「PR作成時に日本語レビューを流せばよいのでは」という提案があった。
ADR 0024は「文書の完成時に1回だけレビューする」ために完成の合図をコミットに置いた。PRの作成は、それより強い完成の合図である。

## 決定

1. `gh pr create` の直前に、PreToolUse(Bash) のフックが1回だけ止めてレビューを依頼する。2回目は止めない
2. 対象は、baseとの分岐点（`git merge-base`）からHEADまでの差分にある日本語の文書とする。
   baseは `--base` / `-B` の指定、無ければ `origin/HEAD`、`main`、`master` の順に決める。
   追加した行の日本語が100字未満のファイルと、ADR 0024の決定7で外す使い捨てのファイルは対象にしない
3. `Co-Authored-By: Claude` の行が付いたコミットで変わったファイルを、Claudeが書いたものとみなして自動でレビューを依頼する。
   それ以外のファイルは一覧にして、レビューに含めてよいかをユーザーに確かめるよう指示する
4. レビュワーには、ブランチで変わった行（`git diff <base>...HEAD`）だけを直させる
5. PR作成の判定は、コマンドの位置にある `gh pr create` に限る。引用符の中の文字列はPRの作成とみなさず、
   `bash -c` などに渡した文字列の中だけを1段調べる
6. baseを決められないなど、候補を決められないときは、1回止めて理由を伝える。黙って通さない
7. 止めた記録は、ブランチごとに残して消さない。以降のPR作成は通し、レビュワーが起動したかの確認は、
   会話記録が伸びた後に1回だけ行う
8. Write・Editの記録（PostToolUse）はやめる。setup.shをやり直す前の古い `settings.json` が呼ぶので、
   `post-tool-use` は何もしない入口として残す
9. Confluenceへの投稿前のレビュー（ADR 0024の決定2）は変えない

## 検討した代替案

**コミット時のレビューを残し、PR作成時は取りこぼしを拾い直すだけにする**

採らなかった。PRを作らないリポジトリでもレビューが動く利点はある。しかし、コミットの見分けの取りこぼしと取り違えが残るうえ、
止める回数が増える。ユーザーが、PR作成時への一本化を選んだ。

**差分にある日本語の文書をすべて自動でレビューする**

採らなかった。ユーザーがエディタで書いた文書まで書き換えてしまう。ADR 0024で「更新時刻で拾う案」を退けたのと同じ理由である。

**Claudeが書いたファイルを、セッションのWrite・Editの記録で見分ける**

採らなかった。Bash経由の書き込みと、別のセッションで書いたファイルを拾えない。
`Co-Authored-By: Claude` の行は、このリポジトリのコミットの決まりで必ず付くので、ブランチの履歴から決められる。

**コマンド全体の文字列を正規表現で探す**（最初の実装）

採らなかった。2026-10-04の実装中に、コミットメッセージに書いたPR作成のコマンドを誤検知した。
誤検知でも1回止めた記録が残るので、本物のPR作成がレビューなしで通ってしまう。

**2回目で止めた記録を消す**（ADR 0024と同じ形）

採らなかった。2026-10-04のこのセッションで、1回のBashにつきフックが2回呼ばれる現象が起きた
（状態ファイルに残った会話記録の位置から推定した。原因は特定していない）。
記録を消すと、2回目の呼び出しが通し、次のBashでまた止めるので、止める・通すが交互になる。
ADR 0024の形は、通すときに書き込みの記録も消していたので、結果的にこの問題が表に出なかった。

## 結果

- Bash経由で書いた文書と、別のセッションで書いた文書もレビューされる
- コミットの見分けの取りこぼしと取り違えは、問題として無くなる
- PRを作らないリポジトリと、Claude Codeの外（ブラウザなど）で作ったPRでは、レビューは動かない
- 止めた記録を消さないので、同じセッション・同じブランチで2つ目のPRを作るときは止めない
- ヒアドキュメントの本文の行頭にPR作成のコマンドがあると、PRの作成とみなして1回止める（ADR 0024と同じ既知の制約）
- Codexでは動かない（ADR 0024と同じ）
