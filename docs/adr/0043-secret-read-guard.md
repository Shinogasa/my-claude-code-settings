# secret を含むファイルの読み取りを、deny・場所と権限のフック・構造だけの読み口で止める

## 背景

Claude Code が作業中にうっかり secret のファイルを読み、値を出力してしまう事故を、置き場所が増えても一覧の追加なしで止めたい。

2026-10-29の失敗調査で、AIが `~/.codex/config.toml` と `~/.zshrc.local` を読み、secret の値を2回出力していたと分かった。
どちらも値を伏せる正規表現が一致せず、値がそのまま出た。effort を high にした後の出来事で、考える深さでは防げなかった。

`permissions.deny` には20件の Read 拒否があったが、漏れた2つのファイルは一覧に無かった。
secret の置き場所は `~/.config` 配下やホーム直下のドットディレクトリに散らばっていて、値だけを書いたトークンファイルもある。
`~/.claude/settings.json` の `env` にも `ANTHROPIC_AUTH_TOKEN` がある。

設計: `docs/superpowers/specs/2026-10-29-secret-read-guard-design.md`

## 決定

3層で止める。対象は Claude Code の Read・Grep・Bash で、うっかり読んで出力してしまう事故を防ぐ。

1. `permissions.deny` を広げる。漏れていた場所と、`~/.config` 配下の名前のパターン（`*token*` など）を足す
2. 新しい PreToolUse フック `hooks/guard-secret-read.py` で、一覧に無いファイルも「場所 × 権限」で止める。
   場所は `~/.config` 配下とホーム直下のドットディレクトリ、権限は本人だけが読めること。判定できなければ止める
3. `bin/show-config-structure` で、キー構造だけを出す。値は許可したキーのものだけを出し、伏せ方は値の形を見ない

決めた人: 守り方の方向（読み取り前に止める）は、利用者が予測の問いで選んだ後、AIが3層に具体化し、利用者が2026-10-29に承認した。
Codex を対象から外すことは利用者が決めた（2026-10-29、今はCodexを使っていない）。MCP のファイル読み取りツールを外すことは、AIが提案し利用者が承認した。
フックのファイルが無いときの扱いと、守る範囲を事故に絞ることは、AIが提案し、利用者が2026-10-30に承認した。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 出力側で値を伏せる（値の形で検出する） | 検出が外れると値がそのまま出る。2026-10-29の2回の漏えいがこの型だった。値だけのトークンファイルは、種類ごとにパターンを足さないと拾えない |
| パスの一覧だけで止める | 置き場所が増えるたびに足す必要がある。漏れた2件は、一覧への追加漏れで起きた |
| sandbox で OS のレベルで止める | SSH での git push、Go 製 CLI の TLS 検証が失敗するなど、影響が大きい |
| `guard-dangerous-bash.py` に判定を足す | Codex（`codex/hooks.json`）と共有している。別のフックにして Claude Code にだけ登録すれば、Codex の振る舞いが変わらないことを配線で保証できる |
| 層3で `hooks`・`statusLine`・`permissions` の値を出す | コマンド文字列やルール文字列にトークンを直書きしうる。中身は `settings.json.template` で読める |
| ホーム全体の600のファイルを止める | 学習store など、リポジトリ配下の600のファイル（`~/garage` 配下に169件）まで止まる |

## 結果

- 守るのは、うっかりの事故だけである。`python3 -c` の中でパスを組み立てる経路など、意図して回り込む形は塞がない。
  **プロンプトインジェクション（読んだページやファイルに仕込まれた指示に従って、AIが意図して回り込む攻撃）による持ち出しは、このガードでは防げない。**
  フックはコマンドの文字列から推定しているだけなので、意図して書き換えたコマンドは見抜けない。防ぐには OS のレベルで止める sandbox が要る。sandbox の再検討は backlog で扱う
- フックのファイルが無いときは、既存の決まり（`tests/test_missing_hook_files.py`）に従って止めずに通す。
  fail-close が対象にするのは「入力を判定できないとき」で、「フックが配置されていないとき」は別の状況として扱う。
  ファイルが無くなるのは設定リポジトリのブランチを切り替えたときで、そこで全 Bash を止めると作業ができなくなるため。
  この扱いを secret 読み取りガードだけ変えるかは、backlog で見直す
- `~/.claude/settings.json` を AI が直接読めなくなる。構造は `show-config-structure` で見る
- Codex と MCP のファイル読み取りツールは対象外。backlog で扱う
