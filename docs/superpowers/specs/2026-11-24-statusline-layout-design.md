# ステータスラインの3段化と幅への追従

## 目的

worktreeで作業すると、リポジトリ名・ブランチ名・worktree名が長くなり、1行目が端末の幅からはみ出す。
あわせて、作業中に確かめたい情報が足りていない。利用者がステータスラインを見るのは、次を確かめたいときである。

1. 今どのリポジトリで作業しているか
2. バジェットの残り
3. プロンプトキャッシュが残っていて、効率よく作業できるか
4. コンテキストが上限に近づいていないか

## ゴール

- 3段に固定し、各段の項目は常に同じ位置に出す
- `COLUMNS` を読み、幅を超えた段は決まった順に縮めて、はみ出さないようにする
- キャッシュの状態（残り時間とヒット率）と、PR番号・レビュー状態を新しく出す

## 非ゴール

- 項目の並びを幅に応じて組み替えること（却下した案C）
- git呼び出しのキャッシュ化（今回の範囲では表示が遅いという問題は出ていない）
- `vim.mode`、`fast_mode`、`added_dirs`、`version` の表示

## アンチゴール

- 幅によって、リポジトリ名が消えたり、1段目・3段目の項目が別の段へ移ったりすること
  （2段目は例外。下の「幅を超えたときの縮め方」の3を参照）

## 段の割り当て

```
📁 my-claude-code-settings 🌲 model-picker-company-profile ⎇ ● #123 approved
🤖 Opus 5.5[⚡high] 🏢WORK 💳 $120/$300   [▓▓▓░░░░░░░] 34%  🔥cache 4m (hit 92%)
🪙 120K↓/8K↑ 💰 $1.23 +40/-3 ⏱ 1h2m 🕐 14:05
```

| 段 | 内容 | 根拠 |
|---|---|---|
| 1 | 📁 リポジトリ名、🌲 worktree名、⎇ ブランチ名と dirty 表示、PR番号とレビュー状態、📌 セッション名、🤝 エージェント | 目的1 |
| 2 | モデル・effort・thinking、プロファイル、バジェット、コンテキストのバー、キャッシュ | 目的2〜4 |
| 3 | トークン数、コスト、変更行数、経過時間、output style、時刻 | 利用者が挙げなかった項目 |

- バジェット: WORK では 💳 LiteLLM 利用額、PERSONAL では 📊 5h / 7d を出す。`rate_limits.spend_limit` があれば併せて出す
- ブランチ名が `worktree-<worktree名>` の形なら、名前を2回出さない（⎇ の後ろはブランチ名を省き dirty 表示だけにする）
- キャッシュ: `prompt_cache.warm` と `expires_at` から残り分数、`hit_ratio` からヒット率を出す。`prompt_cache` が無ければ出さない。
  冷えていれば冷えたと分かる表示にする
- PR: `pr.number` と `pr.review_state`。`pr` が無ければ出さない

## 幅を超えたときの縮め方

表示幅は、ANSI の色コードを除き、絵文字と全角文字を2桁として数える。

幅は `COLUMNS` から読む。公式ドキュメント（https://code.claude.com/docs/en/statusline）によると、
Claude Code はスクリプトを実行する前に `COLUMNS` と `LINES` を端末の大きさに設定する。
出力は捕捉されるため、`tput cols` などでは幅を取れない。`COLUMNS` が無ければ縮めない。
実セッションで `COLUMNS` が届くことを確かめる。

1. 3段目: 時刻 → 経過時間 → 変更行数 → トークン数 の順に落とす。コストは落とさない。
   時刻は端末やOSの時計でも見られるので、最初に落とす（利用者が選んだ順）
2. 1段目: セッション名 → ブランチ名 → worktree名 の順に中央を `…` で省略する。各名前は8文字までは残す。
   リポジトリ名は省略しない
3. 2段目: 縮めず、幅を超えたら端末の折り返しに任せる。目的2〜4の中心なので、一部が欠けるより
   折り返して全部見えるほうを選んだ（利用者の判断。決まった順に縮める案は退けた）

## 検討した案

| 案 | 内容 | 採否 |
|---|---|---|
| A. 3段固定 | 段ごとに並べるだけ | 却下。狭い端末やペイン分割で再びはみ出す |
| **B. 3段固定 + 幅に応じて縮める** | 段の割り当ては固定、超えた分だけ決まった順に削る・省略する | **採用**（利用者が会話で選んだ）。項目の位置が変わらず、目で探す場所が決まる。はみ出しも防げる |
| C. 幅に合わせて自由に流し込む | 優先度順に詰め、段を折り返す | 却下。幅で位置が変わり、ちらっと見て確かめる使い方に合わない |

## AIが決めたこと

- 色のしきい値は既存と同じ 70% で警告色、90% で危険色にそろえる
- 中央省略しても、各名前は8文字までは残す

## 実装者に任せること

- 表示幅の数え方の細部（結合文字など）
