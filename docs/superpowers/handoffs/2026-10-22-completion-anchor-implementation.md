## 3. クラウドでは動かないもの（必ず読む）

このリポジトリのフックは、ユーザーの端末の `~/.claude/settings.json` から動いている。クラウドでは動かない前提で、次を守る。

- 全件テスト: PR作成のフックが確かめる `bash tests/run.sh --all` を、コミットのたびではなく、作業の最後に自分で流す。
  `tests/test_setup_cli.py` と `tests/test_setup_preflight.py` は `setup.sh` を実行し、macOS前提の箇所がある。Linuxで落ちたら、
  それがこの変更によるものか、環境の違いによるものかを切り分けて報告する。環境の違いで落ちたものを直そうとしない
- 原則レビュー・日本語文書レビュー: ローカルではコミットやPR作成のときにフックが求める。クラウドでは動かないので、PRの作成はローカルへ戻ってから行う
- 公開リポジトリの禁止パターン（`.githooks/pre-commit`）: クラウドで `git config core.hooksPath .githooks` が設定されていなければ動かない。
  ユーザー名入りの絶対パス、社名、内部URLを書かない
- 代表検証（計画Task 5 Step 2）: ユーザーの端末の `~/.claude/` で読み込まれたruleの振る舞いを見るものなので、クラウドではできない

**事例（2026-10-22、ある脆弱性への対応）**

並列で進めたのは次の2つだった。本体のエージェントが修正のPRを作り、バックグラウンドのサブエージェントが社内wikiに報告資料を書いた。

| 観点 | 状況 |
|---|---|
| 書き込み先 | 修正はGitのブランチ（worktree）、資料はwikiのページ。重ならない |
| 入力 | どちらも、それまでの調査結果だけで始められた |
| 後から渡す情報 | 資料側は修正の成果（PRのURL、レビュー後に確定した事実）を必要とした。親が途中から追加指示で渡した |
| ユーザー確認の時点 | 資料側は投稿の直前に1回だけ必要だった。日本語レビューのフックが承認を求めたため。親が `AskUserQuestion` で聞いて中継した |
| 共有資源 | ほぼ無い。Dockerは修正側だけが使った |
| 想定外 | 資料側が投稿でフックに止められ、承認待ちで一度戻ってきた。親が中継の手順を知らないと止まったままだった |

**既存の仕組みで賄える部分と賄えない部分**

| 段階 | 既存で賄える | 賄えない |
|---|---|---|
| 発火 | superpowers の `dispatching-parallel-agents` の description にモデルが合うと判断したとき | 複数タスクがあれば必ず判定する強制 |
| 判定 | 状態を共有しないか、同じファイルを触るか（dispatching）。writing-plans の Files / Interfaces | 書き込み先（Gitの外も含む）、ユーザー確認の時点、後から渡す依存、共有資源 |
| 起動 | 同じ応答で複数呼ぶ | 並列か逐次かの切り替え、worktreeの割り当て、バックグラウンド実行と途中からの追加指示 |
| 中継 | 無い | 承認待ちで戻ったサブエージェントの扱い。エージェントの報告をユーザーの承認として扱わないこと |
| 統合 | 要約を読む、衝突を確かめる、全体テスト（dispatching） | Gitの外の成果物の確認、マージ順、統合後の検証 |

### 4.2 テストの一時リポジトリを、ignoreされたファイル抜きで作る → 着手条件待ち

- 背景: `tests/test_setup_preflight.py` と `tests/test_setup_cli.py` の `copy_repository()` は、作業ツリーからディレクトリを丸ごとコピーする。
  ignoreされた生成物（`rules/persona.md`）があるリポジトリ直下では、`personas/` のコピー漏れが隠れ、PR #98 から20件のテストがworktreeでだけ落ちていた。
  PR #100 でコピー漏れは直したが、同じ型の事故は防げていない
- 決めた方針（ユーザー、2026-10-22）: 追跡ファイルだけからコピーする。ただし外すのはignoreされたファイルだけにし、
  `git ls-files --cached --others --exclude-standard` で列挙する。`git ls-files` だけだと、TDD中の `git add` 前のファイルが抜ける
- 着手条件: ユーザーが今回は作らないと決めた。着手条件はユーザーに確認して書く。分からなければ「未定（2026-10-22にbacklogへ積んだ）」と書く

### 4.3 CIで全件テストを流す → 着手条件待ち

- 利点: 毎回まっさらな環境で流すので、コピー以外から入る環境依存（HOME、グローバルなgit設定、ツールのバージョン）も捕まえられる。
  `hooks/require-full-tests-before-pr.py` は「CIが無いので記憶頼みになる」ために作られたので、CIがあれば外せる可能性がある
- 懸念: macOS前提の箇所（`setup.sh`、`sed -i ''` など）がある。Linuxのランナーではそのまま動かない可能性がある。macOSのランナーは料金が高い
- 着手条件の案: 環境依存の事故がもう一度起きたとき
