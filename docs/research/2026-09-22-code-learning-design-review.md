## 所見と改訂案

### 1. High: 一工程の成功から、一連の作業を本人へ渡す契約が不足する

- 根拠: 改訂前設計書77–85行。Investigateでは一つの行動を委ね、局所修正の成功後に支援を一つ減らす。
- 条件: 毎回AIが課題・対象関数・回帰テストを選び、ユーザーが部分修正だけを成功させる。
  または調査を成功させても、局所修正の成功という移行条件に該当しない。
- 影響: 規約を守りながら、小問への回答が上手になる状態に留まれる。
  自分で調査箇所と次の行動を選び、検証まで進めるという目的の証拠が得られない。
- 最小修正: 一工程、小さな実課題の一連の作業、通常作業での自発行動を区別する。
  支援を減らすだけでなく、本人が次の工程を選ぶ範囲を広げる。開始時に担当範囲と完了条件を示す。
- 受入条件: 小さな実課題で本人が調査方法と検証方法を選び、AIの完成テストを利用した場合は
  「本人が検証を設計した」と記録しない。改訂案の第5・12節へ反映。

### 2. High: 再試行1回と早い答えの開示が、本人による完遂を中断する

- 根拠: 改訂前設計書91・95–97行。理由回答後の開示を許し、再修正の機会を一度作って通常作業へ戻る。
- 条件: 最初の修正と次の修正に誤りがあり、本人には継続する意思がある。
  または理由回答直後に模範解を開示し、その後に本人へ再修正を求める。
- 影響: 今回の「時間より自力でやり切ることを優先」という希望に反する。
  答えを写した修正と、反例から本人が原因を考え直した修正も区別しにくい。
- 最小修正: 同じ担当範囲では再試行回数や時間で引き取らない。完成解は理由回答だけでは開示せず、
  反例・観測差から本人の再調査へ戻す。停滞時は前提の補足・範囲調整を行う。
  本人の中断・引取り希望と安全上の介入は尊重し、未回答からの自動引取りはしない。
- 受入条件: 2回以上の再試行でも本人が続けられ、支援付き完遂と独立成功を別に報告する。
  中断・再開で同じイベントを二重集計しない。改訂案の第4–8・12節へ反映。

### 3. Medium: 支援の減少だけでは、課題の易化や促された行動と区別できない

- 根拠: 改訂前設計書129・133・164–166・292–295行。
  自発的な行動の利用と支援履歴はあるが、開始契機と課題間の比較条件は記録契約に指定されていない。
- 条件: 初回は未知のコードと曖昧な症状、次は対象箇所とテストが既知の課題。
  またはAIが毎回「次は回帰を確認して」と指示した後の成功を並べる。
- 影響: 支援が減ったように見えても、本人が実務で必要な行動を選べるようになったかは分からない。
- 最小修正: 担当範囲、開始契機、既知の箇所・仮説・検証、本人が選んだ次の行動を本文に残す。
  pilotでは少数の能力について比較条件を揃え、観測機会なしとAIが担当を渡さなかった場合を区別する。
- 受入条件: 促された行動を自発行動にせず、比較不能なら成果判断を保留する。
  新しい総合スコアや能力DBは作らない。改訂案の第7・8・12節へ反映。

### 4. Medium: 訂正の分岐を検出した後、保存契約内で解消できない

- 根拠: 改訂前設計書151–154・215–216行。supersedesは直前1件、書込時は現在の末尾を要求する。
- 条件: 2台が同じ記録AからBとCへ独立に訂正し、Gitで両方を取り込む。
- 影響: listは競合を返すが、DからBだけを置換するとCが残る。B/C両方を置換する表現がないため、
  通常の記録操作では1有効レコードへ戻せない。手作業で履歴を消す誘因になる。
- 最小修正: supersedesをUUID配列にし、通常訂正は1件、明示的な競合解消だけ全末尾を指定する。
  全末尾の一致を排他中に検査し、理由付きの新版を作って旧版を保持する。内容の自動採点・統合はしない。
- 受入条件: A→B/Cから明示的なDへ統合すると有効記録は1件。枝の欠落や古い末尾集合は拒否する。
  参照欠落・破損は別の復元対象とする。改訂案の第8・9・12節へ反映。

## 維持する判断と選択肢

提案は、担当範囲を限定し、その範囲を本人が完了するまで支援する方式。
費用は対話時間が長くなることと、待機中にAIが担当箇所を進められないことである。

- 短い小問と再試行1回を維持: 中断時間は読みやすいが、今回のユーザー希望と合わない。
- 小さな実課題を本人が完遂（提案）: 担当と証拠を明確にできる。前提不足時の補足や範囲調整が必要。
- 毎回タスク全体を無支援で実施: 広い自立性を観測できるが、未知の前提まで同時に要求し、原因の切分けが難しい。

設計Predictの3軸、最初の行動と理由の順序、二層構成、両モードのイベント上限は維持する。
理由質問を全廃・統合する提案はしていない。今回の新しい希望は再試行と担当範囲へ反映した。
資料検索を禁じる暗記試験、意図的なproduction欠陥、全件Astra教師、teach導入、常駐hookは追加しない。

公開用の抽象化対象には本文以外の能力ID・ファイル名・operation・取込manifestも含めた。
これは漏えいが見つかったという所見ではなく、公開storeの受入条件の明確化である。

## 根拠の確認と限界

ADR 0001・0007・0012、現行の両ルール、code-learning skill、両learning README、
初期の模擬評価、親ルーティング運用引継書を確認した。既存案が既に解決している
Write固定優先、二重出題、誤答ほど良いという主張、長期保持と即時転移の混同は新規所見に数えていない。

[Bisra et al. (2018) の出版社公開abstract](https://link.springer.com/article/10.1007/s10648-018-9434-x)で、
自己説明を促す介入のメタ分析であることを確認した。全文は購読制限があり、全文読了とは扱わない。
このabstractは、行動と理由を必ず別ターンで尋ねる方式の優位性や本設計全体を直接検証していない。
[Richland et al. (2009) の著者公開PDF](https://learninglab.uchicago.edu/Pre-Testing_files/RichlandKornellKao.pdf)の
abstract・課題説明では、文章を学ぶ前の不成功な検索にも後続テストの利益を認めている。
実務エンジニアの誤答を増やすべき、長時間悩むほど良い、という主張へは拡張しない。

今回の改訂はユーザーの目的と設計上の反例に基づく提案。実ユーザーの成長や教師の採点精度は未実証。
hosted modelでの両ホストの自動発火・複数ターンの開示順・保存までの完走も今回の検証対象外である。
ルールの文章検査だけで、これらが動いたとは判定しない。
