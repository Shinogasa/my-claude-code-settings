# code-learning skill の初期挙動試験

## 方法と限界

架空のTypeScript依頼を、読み取り専用のfresh subagent（`gpt-5.6-luna` + `medium`）へ渡した。
baselineは新skillを読ませず、guidedは `skills/code-learning/SKILL.md` を全文読ませた。
いずれも最初の応答だけを比較した。モデル、既存の学習指示、評価promptは完全には盲検化していない。
実ユーザーの回答、実コードの検査、転移課題、Claude Code/Codexの新規session起動はまだ試験していない。

| ケース | baselineの観測 | guidedの観測 | 判定 |
|---|---|---|---|
| 金額計算の実装 | 完成した `total` 関数を提示し、「ユーザーにコードを書かせず、完成コードを提示しました」と報告 | 完成コードを提示せず、ユーザーへ関数本体と境界ケースを委ねて停止 | 初回の能動的Writeは改善 |
| 非同期関数のレビュー | 既存の設計Predict形式で `fetch` / `Response` / `response.json()` の選択肢を提示して停止 | 成功・キャンセル・HTTP応答・JSON解析の流れを追うReview課題を提示して停止 | 形式の違いを観測。学習効果は未検証 |
| Sender選択とFactory | 既存の設計Predict形式で実装選択肢を提示して停止 | やはり設計選択肢を提示して停止 | 新skill固有の改善は観測できず。設計Predictとの競合は後続の統合試験が必要 |

最初のguided実装回答は「実装を書いたら、なぜそのエラー処理にしたか説明してください」と、
コード提出前の依頼に理由質問を同梱した。skillへ「コードまたは指摘を見てから次の応答で理由を問う」
という順序を明記して同じケースを再試験した。再試験では完成コードも理由質問も先出しせず、
ユーザーの実装を待って停止した。

この試験から、初回応答で完成コードを渡さないことは確認できたが、採点の正確さ、
転移、複数ターンでの停止順序、両ホストの自動発火、教師routeの安全性は証明できない。
それらは実セッションのscenarioとpilotで別途検証する。

## 追加scenario（同日、読み取り専用の模擬評価）

最新のruleとskillを読ませたagentに、互いに独立した架空の依頼を提示した。
これは**指示内容の整合性を調べるsimulation**であり、両ホストの自動発火や
実ユーザーの学習成果を示さない。

| ケース | 期待する停止・出力 | 観測 | 未検証 |
|---|---|---|---|
| 明示的な「急ぎ・全部やって」 | コード学習をOFFにして通常実装へ | OFFを宣言し、実装・検証へ進む応答 | 実コードの完成 |
| 課題提示後のskip | 理由を強制せず通常実装へ | skipを受け入れ、理由を問わない | 実装完了までの継続 |
| 生成lockfileだけの差分 | 発火しない | 除外を表明 | 自動候補検出 |
| AI初稿のエラー伝播修正 | 教材用の欠陥を作らずModifyを検討 | 既存コードと失敗テストを確認する応答 | 実際のModify停止 |
| Writeの複数ターン | コード提出後に理由を一問、検査後にfeedback、条件を一つ変えて転移 | 順序どおりの模擬応答。実検査をしていないため `verified_fact` なしと明示 | 本物のテスト、採点精度、転移成功 |

最後の複数ターン例では、agentが「妥当な提出コード」と架空のユーザー回答を自作した。
したがって `★ Code Delta` は出力形式の例にすぎず、実ユーザーの能力記録には使えない。
理由質問も二つの細部にまたがったため、実運用では一つの能力へさらに絞る必要がある。

### 実セッションで残すscenario

次のpromptと期待観測は固定したが、まだ実ホストで実行していない。

| ケース | 入力の要点 | 期待観測 | 状態 |
|---|---|---|---|
| 既習 | 別文脈2回、2回目は実質ヒントなしで同能力を示した記録がある状態で、同程度の実装を依頼 | 同じ難易度の再出題は避ける。ただし記録なしを未習得と断定しない | 未検証 |
| 設計Predictとの同一箇所重複 | Factory採否の設計判断と、その実装が同じ箇所に現れる依頼 | 判断基準か実コード技能の一方を選び、二重に停止しない | 未検証 |
| 未検証feedback | 使用中のframework APIの挙動を実行・一次資料で確認できない状態で、AI初稿の採点を求める | 推測を `verified_fact` にせず、検証できなければ学習イベントを見送る | 未検証 |
| 実Review | 文脈・テスト付きのAI初稿を示し、失敗経路のレビューを依頼 | ユーザーの指摘と理由を待つまで ★ Review / ★ Code Delta で答えを先出ししない | 未検証 |

現時点の実測は、manifestと一時HOMEに対するsetupのリンク検査、および静的契約テストまで。
Claude Code / Codex の新規sessionでの**暗黙の自動発火**、Write・Modify・Reviewの実停止、
除外・OFF・skip、検証付きfeedbackは未検証。pilotの開始条件を満たしたとは扱わない。
