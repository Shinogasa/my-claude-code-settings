## 合理化防止

次のように考えたら、それは回避の兆候である。

| 思考 | 現実 |
|---|---|
| 「急いでいそうだから省く」 | OFFにするのは明示の指示があったときだけ。推測で省かない |
| 「もう説明したから予測は不要」 | 説明した後の質問は読み直しであり、想起にはならない。説明の**前**に問う |
| 「後でまとめて聞く」 | 開示した後の予測は事前予測にならない。順序が何より大事 |
| 「調べ物だから対象外」 | 調査は、原因分析の予測がいちばん役に立つ場面 |
| 「後で予測を聞けばいい」 | 結論・推奨・実装方針を書き始めた後に聞くと、停止は成立しても事前予測にならない。回数は満たすが、仕組みとしては何も働いていない |
| 「理由まで問うのは冗長だ」 | 理由のない選択は記録として価値が無い。結論だけの記録は後から一切使えない |
| 「良い判断だったので指摘がない」 | 全軸が埋まっているなら、その基準が破れる条件を出す。何も指摘せずに終えるのは、評価を投げ出すことになる |
| 「一般的な次の問いを挙げておこう」 | 一般論は行動に結びつかない。今回のケースに即した言葉で言えないなら、評価できていない証拠 |
| 「次の問いにも軸名を書いておこう」 | 軸は評価パートで名指し済み。同じ軸名を2回書くと、いちばん伝えたい差分が目立たなくなる |
| 「承認されたから判断点は済んだ」 | 承認は判断の記録ではない。「OK」で通った回こそ、何が検討されなかったのかが分からない |

### 下限を外したことで復活する回避（2026-08-14 追加）

**下限の撤廃は、「判断点が無い」と言えば省けるという意味ではない。**
省いてよいのは発火条件（3条件と層ゲート）を満たさないときだけで、判定は条件に照らして行う。

| 思考 | 現実 |
|---|---|
| 「今回は判断点が無かった」 | 3条件（不可逆・競合・一般化可能）に照らしたか。照らさずに直感で言っているなら、それは判定ではない |
| 「複数案を出したので必ず問う」 | 複数案だけでは強制発火しない。3条件と層ゲートを個別に確認する |
| 「選択肢の理由まで書くと止まりすぎる」 | 理由フェーズは1問1メッセージで数十秒。止まりすぎるなら、減らすのは理由ではなく発火回数 |
| 「どれも成立する選択肢を3つ作れないから2択にする」 | 2択でよい。**無理に捨て案を足すより、案を減らす方が正しい** |
| 「予測が当たり続けているので習得した」 | 結論の一致は習得の証拠ではない。支援量と、別文脈での理由・検証を確認する |

### 層ゲートの導入で復活する回避（2026-08-21 追加）

| 思考 | 現実 |
|---|---|
| 「L1の判断も3条件を満たすから拾ってよい」 | 3条件は層を制約しない。層ゲートは**独立した4つ目の条件**であり、3条件を満たしてもL1で発火してよい理由にはならない |
| 「今日の作業にはL2以上の判断が無かった」 | 探したか。移行手順・切り戻し可能性・観測点・境界の位置は、コードを触るほぼ全ての変更に付いてくる。「見つからない」は「探していない」と区別がつかない |
| 「L2かもしれないので拾っておく」 | 層を判定できないときはL1とみなす。曖昧な回を拾い始めた時点で、ゲートは意味を失う |
| 「定石が思いつかないので省く」 | 省いてよいのは、コードを伴わない判断のときだけ。コードを書いた回で思いつかないのは、調べていないだけ |
| 「定石は概念より具体的だから2つ出しておこう」 | 上限は `概念` と合わせて2つ。定石を複数並べると、どれも定着しない |
