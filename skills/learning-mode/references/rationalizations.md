## 合理化防止

以下を考えたら、それは回避の兆候である。

| 思考 | 現実 |
|---|---|
| 「急いでいそうだから省く」 | OFFは明示指示のみ。推測で省くな |
| 「もう説明したから予測は不要」 | 説明後の質問は再読であって想起ではない。説明の**前**に問え |
| 「後でまとめて聞く」 | 開示後の予測は事前予測にならない。順序が本質 |
| 「調べ物だから対象外」 | 調査こそ原因分析の予測が効く場面 |
| 「後で予測を聞けばいい」 | 結論・推奨・実装方針を書き始めた後に聞くのは、停止が成立しても事前予測にならない。回数は満たすが機構としては空になる |
| 「理由まで問うのは冗長だ」 | 理由のない選択は記録として無価値。結論だけの記録は後から一切使えない |
| 「良い判断だったので指摘がない」 | 全軸が埋まっているなら、その基準が破れる条件を出せ。無指摘で終えるのは評価の放棄 |
| 「一般的な次の問いを挙げておこう」 | 一般論は行動に変換されない。今回のケースの具体語で言えないなら、それは評価できていない証拠 |
| 「次の問いにも軸名を書いておこう」 | 評価パートで名指し済み。同じ軸名を2回書くと、最も伝えたい差分が埋もれる |
| 「承認されたから判断点は済んだ」 | 承認は判断の記録ではない。「OK」が通った回こそ、何が検討されなかったか分からない |

### 下限を外したことで復活する回避（2026-08-14 追加）

**下限の撤廃は「判断点が無い」と言えば省ける、という意味ではない。**
省いてよいのは発火条件（3条件＋層ゲート）を満たさないときだけで、判定は条件に照らして行う。

| 思考 | 現実 |
|---|---|
| 「今回は判断点が無かった」 | 3条件（不可逆・競合・一般化可能）に照らしたか。照らさずに直感で言っているなら、それは判定ではない |
| 「複数案を出したので必ず問う」 | 複数案だけでは強制発火しない。3条件と層ゲートを個別に確認する |
| 「選択肢の理由まで書くと止まりすぎる」 | 理由フェーズは1問1メッセージで数十秒。止まりすぎるなら、減らすのは理由ではなく発火回数 |
| 「competitive な選択肢が作れないから2択にする」 | 2択でよい。**作れない捨て案を足すより、案を減らす方が正しい** |
| 「予測が当たり続けているので習得した」 | 結論の一致は習得の証拠ではない。支援量と別文脈での理由・検証を確認する |

### 層ゲートの導入で復活する回避（2026-08-21 追加）

| 思考 | 現実 |
|---|---|
| 「L1 の判断も3条件を満たすから拾ってよい」 | 3条件は層を制約しない。層ゲートは**独立した4つ目の条件**。3条件の充足は L1 で発火してよい理由にならない |
| 「今日の作業には L2 以上の判断が無かった」 | 探したか。移行手順・切り戻し可能性・観測点・境界の位置は、コードを触るほぼ全ての変更に付随する。「見つからない」は「探していない」と区別がつかない |
| 「L2 かもしれないので拾っておく」 | 層を判定できないときは L1 とみなす。曖昧な回を拾い始めた時点でゲートは無効化する |
| 「定石が思いつかないので省く」 | 省いてよいのはコードを伴わない判断のときだけ。コードを書いた回で思いつかないのは、調べていないだけ |
| 「定石は概念より具体的だから2つ出しておこう」 | 上限は `概念` と合わせて2つ。定石を複数並べるとどれも残らない |
