# dotfiles: cmux 外観設定の管理パス選定

`#dotfiles` `#設計判断` `#可観測性`

**問いかけ:** Application Support（cmux が最優先で読むが macOS 固有・上流 ghostty のアプリID依存）と XDG（OS非依存でリポジトリの XDG 準拠方針とも整合するが探索優先度が低い）、どちらを選ぶ？

**自分の説明:**
A。B だとそもそも聞いていなかったりエラーだったりがユーザーにわかりやすくないので気が付かない。

**補足:**
「壊れ方が見えるか」を選択基準に置いた判断。B（XDG）は Application Support 側にファイルが存在すると警告なく無視されるため、設定が効かないという症状だけが残り調査の起点が立たない。A は将来 cmux が自前アプリIDへ移行した際に一斉に効かなくなるので、異常として認識できる。「確実に動く」より「失敗が観測できる」を優先した設計判断で、可観測性を可用性より上に置く一般的な原則として応用が利く。なお A 固有のリスク（アプリID依存）は、README にトラブルシュート手順（`ghostty +show-config` で実効値を確認）を残すことで、壊れた際の調査コストを下げる形で緩和した。
