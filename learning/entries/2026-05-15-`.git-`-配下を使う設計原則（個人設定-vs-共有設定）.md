# `.git/` 配下を使う設計原則（個人設定 vs 共有設定）


**問いかけ:** 今回 `.gitignore` 編集ではなく `.git/info/exclude`、共有 hook ディレクトリではなく `.git/hooks/` を選んだ。「`.git/` 配下を使う設計判断には共通する原則がある」と気付いたか？

**自分の説明:**
個人設定は .git 配下使う。

**補足:**
本質を一言で捉えている。原則は「`.git/` 配下＝Git 自身の追跡対象外＝自分のクローンだけに効く」。
今後の判断軸として:
- 共有したい（チーム全員に効かせたい）→ tracked ファイル（`.gitignore`、`.githooks/` + `core.hooksPath` 等）
- 個人だけに効かせたい → `.git/` 配下（`.git/info/exclude`、`.git/hooks/`、ローカル `.git/config` 等）

この対比を持っておくと、「これは個人だけに効かせたい」と思った瞬間に `.git/` 配下の選択肢を即座に手繰れる。
