# 全軸充足をどう記録するか

### 判断点: 3軸すべてが埋まっていた回を、集計可能な記録としてどう表すか

`axis` の値は「3軸の軸名 / `未記録` / `null`」の3種類しかなく、
名指しする軸が無い回は `未記録`（記載漏れと同じ値）に落ちていた。

**予測:** `全軸充足` を4つ目の値として追加する。

> 名指しする軸がないなら全軸充足と行っても問題なさそうだと重たので

**実際:** 同じ結論。`全軸充足` を追加した。

**差分（予測に含まれていなかった観点）**

`全軸充足` は**評価する側（AI）の自己申告**になる。
「本当に3軸埋まっていた」と「評価を飛ばした」を、値そのものからは区別できない。
`未記録` から救い出したはずの回が、今度は**サボった回を混入させる側**に変わる。
しかも偏りの向きが悪い。機構を設計した側が「効いている」と判定する動機を
構造的に持つため、上達を過大評価する方向へ倒れる。

そこで値だけで完結させず、本文に `### 基準が破れる条件` の見出しを必須にした。

```bash
grep -l '^axis: "全軸充足"$' learning/entries/*.md | xargs grep -L '^### 基準が破れる条件'
```

見出しが無ければ記載漏れとして扱う。実際に見出しを消して**検出されることを確認**した
（消す前は空、消した後はファイル名が出る）。仮説が偽のときに違う出力が出るので、
これは測定になっている。ただし検査できるのは**書いたかどうかだけ**で、
書かれた内容の妥当性は検査できない。

### 欠けた軸: 失敗モード

「問題なさそう」で止まっていて、**この値が汚染される経路**が出ていない。
新しい値を足す判断では「その値が誤って入るのはどんなときか」まで見ないと、
記録が増えた分だけ誤りも増える。

### 副次: 前提の検証

「名指しする軸が無い」＝「全軸充足」という同値を前提に置いているが、
実際には「評価しなかった」も同じ見え方をする。
2つの状態が同じ出力になる時点で、それは区別できていない。

### 概念: 自己申告データ（self-reported metric）

測定対象と測定者が同一のときに得られる値。**測定者に有利な方向へ系統的に偏る**ため、
単独では指標にできない。外形的に検査できる痕跡を1つ紐付けて初めて使える。

### 接続: 過去の判断原則

`2026-08-14-機構の効果を何で判定するかを事前に決める-5.md`

> 判定者に利害があるなら、判定者の裁量が入らない代理指標を必ず1つ添える。

同じ形が出た。今回は「見出しの有無」という裁量の入らない痕跡を添えた。
前回は原則として書き、今回は実装として置いた点だけが違う。

**次に同種の判断で確認する問い**: 記録の値を1つ増やすときは、
**その値が誤って入る経路**を1つ挙げ、外形で検査できる痕跡を紐付けられるか確認する。
