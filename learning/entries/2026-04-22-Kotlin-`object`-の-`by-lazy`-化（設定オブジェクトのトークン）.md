# Kotlin `object` の `by lazy` 化（設定オブジェクトのトークン）


**問いかけ:** 今回 `val token: String = ...throw` ではなく `val token: String by lazy { ...throw }` を選んだ。「なぜ `by lazy` にしたの？」と聞かれたら、Kotlin `object` の初期化の仕組みを踏まえてどう説明する？

**自分の説明:**
オブジェクトは初回アクセス時に初期化が走る。今回利用しない変数があって環境変数に設定していなかった場合、現状だと exception が throw される。不要な環境変数をわざわざ設定する手間をなくしたいので、利用されるときに評価される lazy を利用した。

**補足:**
「初期化のタイミングを object ロード時から実使用時まで遅延させることで、関心の分離を実現した」とも言える。セットアップ用のスクリプトはトークンの関心事の外にいるのに、同じ設定オブジェクトに同居しているだけで巻き添えを食らっていた、という構造的な問題。JVM の `<clinit>` が全 val を一括評価する仕組みがその根本原因。
