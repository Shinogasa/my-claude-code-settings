# IaC リポジトリのオンボーディング（構成把握とメモリ化）


**判断点:** 静的サイト配信の IaC リポジトリを初見で読み、「次に触る人が最初に事故る箇所」を
1つ選んで永続メモリに残す。選択を誤ると、後続の全員が同じ地雷を踏む。

### 予測 1（HIT）

**予測:** 「DNS が IaC 管理外」。DNS 定義ファイルは拡張子を外して無効化され、
コメントは実在しないファイルを参照し、lock ファイルには宣言のない provider が残っている。

**実際:** 一致。履歴を追うと、無効化はリネームによるもので、コメントが指すファイルは
**一度もコミットされていなかった**。lock への provider 追加は同じコミットに含まれており、
ローカル限りの設定で init された痕跡だった。

**予測に含まれていなかった観点:** ファイルから読み取れるのは「定義が無い」ことまでで、
**事故の向きを決めるのは state 側に何が残っているか**である。

```
定義なし × state あり  → 次の plan が destroy を出す（危険）
定義なし × state なし  → lock の残骸なだけ（無害）
```

この2つは影響が正反対なのに、**リポジトリを何度読んでも判別できない**。
だから残すべき知識は「定義が無い」という事実ではなく、
「着手前に state の在庫を実測する」という**手順**になる。

### 予測 2（部分一致）

**判断点:** state ロック機構が存在しない構成で、apply が中断したとき最初に何を見るか。

**予測:** リモートに保存された state を見る。

**実際:** 入口としては正しい。apply 中も一定間隔で中間 state が永続化されるため、
state は進捗をほぼ保持している。ロックが無いので解除操作も不要（皮肉な副作用）。

**欠けていた観点:** **state は「IaC が知っていること」しか映さない。**
中断時の本当の敵は、実インフラには作られたのに state に載っていない孤児リソース。
突合対象は state 単体ではなく `state ↔ 実体` の差分である。

**実務でどう事故るか:**
中間永続の隙間で落ちると、実体はあるが state に無いリソースが生じる。
次の plan は「新規作成」を出し、**plan は綺麗に通るのに apply だけ名前衝突で落ちる**。
名前が固定のリソース（グローバル一意名、エイリアス、ポリシー名）ほど顕著。
plan の成功が安全を意味しないケースで、原因特定に時間を食う。

なお `refresh` 系の操作は state にある物しか照会しないため、**孤児の発見には使えない**。
「差分を取る」という発想でこの操作に手が伸びるが、対象集合がそもそも state 側だけである。

### 一般化: 前回と同じ盲点が出た

直前のエントリで書いた「リポジトリを読んでも見つからない層」が、
別の形で再出現した。今回の内訳:

```
リポジトリから読み取れる層:
  定義ファイルの有無 / コメント / lock の記載

リポジトリから読み取れない層（実測が要る）:
  [a] state の在庫          → 定義の欠落が destroy になるか無害かを決める
  [b] 実インフラの在庫       → 孤児リソースの有無を決める
  [c] 実行環境の資格情報     → そもそもコマンドが起動するかを決める
  [d] state 保管先の設定     → 壊れた state を巻き戻せるかを決める
```

[c] は実際に確認して判明した。provider 定義に認証プロファイル名が直書きされており、
**作業端末にそのプロファイルが存在しなかった**。つまり読解した内容を検証する手段が
最初から無い状態だった。環境変数による上書きも効かない（設定ファイル側の指定が優先される）。

[d] も同様。state の保管先は、chicken-and-egg のため IaC 自身のコードでは管理されない。
結果として**バージョニングの有無がコードから判定できず、「壊れた state を巻き戻す」という
復旧手段が存在するのかどうかすら不明**になる。復旧計画の前提が可視化されていない。

**教訓:** オンボーディングの成果物に書くべきは、読んで分かった構造ではなく
**読んでも分からなかったことを埋める手順**である。前者は次に読む人も同じ労力で再取得できるが、
後者は実測しない限り誰も気づかないまま危険な操作に進む。

**副次的教訓:** 認証情報がコードに直書きされていると、
「設定を読む」と「設定を検証する」の間に環境依存の壁ができる。
レビューは通るが手元で再現できない、という状態を作り出す。
