# 配布先の所有権を実体一致で判定してよいか

## 判断点

設定配布スクリプトを「親ディレクトリを丸ごとリンクする」方式から
「マニフェストに列挙した項目を1つずつリンクする」方式へ移行した。

移行前の親リンクが残っているため、配布先 `<host>/skills/<name>` を lstat すると
symlink ではなく実ディレクトリが見える。ただし realpath はリポジトリ内の
期待ソースと完全に一致している。この状態をどう分類するか。

- A) realpath が期待ソースと一致すれば `linked` とみなす
- B) `conflict` のまま、退避（rename）の前に中断する

## 予測

A) linked とみなす

**判断基準（原文）**: すでに配置されていて各ツールから利用できる状態で一致してあるならば問題ないと判断した

## 実際

B) conflict のまま中断する。

配布先が symlink であることは「配布スクリプトが自分で作った」という証跡である。
realpath の一致は「今この瞬間、同じ内容が見える」という観測でしかなく、
誰がそこへ置いたかを示さない。

## 差分

不一致。反例を1つ。

移行元の親リンクは、マニフェスト外の項目もまとめて露出させている。
実際、ホスト固有と宣言した項目が反対側のホストからも読み込まれている状態が
そのまま残っていた。「実体が一致していて使えるなら問題ない」が成り立つなら
この露出も問題ないことになるが、直前のコミットはまさにこの露出を止めるために書かれていた。

## 評価: 失敗モード

「問題ない」と結論したが、この判断がどう壊れるかを挙げていない。壊れ方は2つ。

1. マニフェストから項目を1つ削除しても、親リンク経由でディレクトリ全体が
   見えているため配布先は消えない。スクリプトは `linked` と判定して何もしない。
   **削除が永久に反映されない。**
2. リポジトリに新しいディレクトリを置いた瞬間、マニフェストに載せる前でも
   両ホストへ露出する。レビュー前の書きかけが発火しうる。

トレードオフも抜けている。B案が持っていた「マニフェストだけが配布物を決める」
性質を捨てているが、そこに触れていない。

## 過去の判断原則との接続

`2026-08-19-setup衝突を確認後に明示置換する-11.md` の末尾:

> 「自動更新してよい対象を、現在値だけでなく何の所有証跡から判定するか」を実装前に決める。

同じスクリプトについて7日前に立てた原則。今回は現在値（realpath 一致）だけで判定した。
原則が文脈をまたいで呼び出せていない。

## 概念

**収束（convergence）** — 宣言した状態へ実体を寄せる操作。「足りないものを足す」だけでは
片道で、「宣言に無いものを外す」が揃って初めて宣言が実体の真実になる。後者を欠くと
過去の配布物が消えないまま積み上がり、宣言を読んでも実体が分からなくなる。

## 定石

**所有権の判定は「内容が一致するか」ではなく「自分が作った形か」で行う。**

```python
# NG: 実体が一致していれば所有物とみなす
if destination.resolve() == source.resolve():
    return "linked"

# OK: 自分が作った形（symlink そのもの）であることを先に要求する
if destination.is_symlink() and destination.resolve() == source.resolve():
    return "linked"
```

内容一致で所有を認めると、他の経路が置いたものと自分が置いたものを区別できなくなり、
「これを剥がしていいか」を後から誰も決められなくなる。

## 学習領域

失敗モードが抜けていた → 今回「一致していて使えるから問題ない」と言ったが、
この判断が誤りだと判明する出来事（宣言から消したのに消えない）を挙げていない。

**次に同種の判断で確認する問い**: 「現状で問題ない」と言う前に、
「この判断が誤りだと後で分かるのは、どんな出来事が起きたときか」を1つ挙げる。
