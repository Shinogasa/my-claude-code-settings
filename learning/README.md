# Learning

★ Predict（予測）と ★ Delta（差分）の記録。仕様は `rules/learning-mode.md` を参照。

> **⚠ このリポジトリは PUBLIC**
> 社名・組織名・プロジェクト名・リポジトリ名・内部ホスト名・内部URL・
> テーブル名・内部パス・業務コードを書かないこと。
> 技術的本質のみを一般化して記録する。判断に迷ったら書かない。
> 詳細は `rules/learning-mode.md` の「抽象化ルール」を参照。

## 構成

```
learning/
├── README.md          運用ルール・集計方法・検証チェックポイント（このファイル）
└── entries/           1エントリ1ファイル
    └── YYYY-MM-DD-<タイトルのスラッグ>.md
```

同じ日に複数書く場合はファイル名末尾に `-2` `-3` を付ける。

## エントリの形式

```markdown
---
date: 2026-08-09
title: "タスク概要"
result: hit
axis: "失敗モード"
---

# タスク概要

### 判断点: 何を判断する場面だったか

**予測:** ユーザーの予測と、その判断基準

**実際:** 実際の判断・原因・リスク

**差分（...）**

...

### 欠けた軸: 失敗モード

**次に同種の判断で確認する問い**: ...
```

### frontmatter

| フィールド | 値 | 意味 |
|---|---|---|
| `date` | `YYYY-MM-DD` | 記録日 |
| `title` | 文字列 | 本文の H1 と一致させる |
| `result` | `hit` / `miss` | 予測が当たったか。`miss` は将来の優先再出題の母集団 |
| `axis` | 軸名 / `未記録` / `null` | 欠けた軸。下記参照 |

### `axis` の3つの値を混ぜないこと

| 値 | 意味 | 集計での扱い |
|---|---|---|
| `"トレードオフ"` / `"失敗モード"` / `"前提の検証"` | 欠けた軸 | 母数に入れる |
| `未記録` | 軸評価の導入後だが記載が無い。**全軸充足か記載漏れかは区別できない** | 母数から除外 |
| `null` | 2026-08-08 の軸評価の導入前。軸という概念自体が無かった | 母数から除外 |

**`未記録` と `null` を同じ「空」として扱うと、傾向ではなく「記録がいつ始まったか」を測ることになる。**
軸名は `rules/learning-mode.md` の3軸から動かさない。言い換えると集計が壊れる。

## 集計のしかた

```bash
# 総数
ls learning/entries/*.md | wc -l

# MISS の一覧（優先再出題の母集団）
grep -l '^result: miss$' learning/entries/*.md

# 軸ごとの件数（未記録・null は自動的に別集計される）
grep -h '^axis: ' learning/entries/*.md | sort | uniq -c | sort -rn

# 特定の軸のエントリ
grep -l '^axis: "失敗モード"$' learning/entries/*.md
```

2026-08-08 以降。この状態で軸別集計をすると、傾向ではなく直近数日の内訳が出る。
`null` が24件ある限り、「どの軸が慢性的に弱いか」は言えない。
