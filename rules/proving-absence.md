# 不在の主張（「無い」と言うときの形式）

## 基本方針

**「Xは無い」は二重の主張である。**

1. 探した範囲にXは無かった
2. **探した範囲は、Xが在りうる範囲を覆っている**

①は走査で示せる。②は走査では示せず、別の根拠が要る。
**②を書かない不在報告には、ほとんど情報が無い。**

**丁寧に調べても、正しいことの証明にはならない。** ①を丁寧にやるほど「調べ尽くした」という感覚だけが強まり、
②が欠けていることに気づきにくくなる。

## なぜ「順序の指示」ではなく「出力の形式」なのか

`rules/ecc-development-workflow.md` のResearch & Reuseは、
「GitHub code search first, **library docs second**」をmandatoryと定めている。
この順序を守っていれば防げたはずの不在の誤認が、それでも起きた。

原因は文面の弱さではない。**順序の指示は、守ったかどうかが成果物に跡を残さない**ことにある。
違反しても出力は正常に見えるので、書いた本人も読み手も気づけない。誰にも気づかれないまま守られなくなるルールだった。

一方、形式の決まりは後から確かめられる。欄が空なら、読めば分かる。
このファイルが順序ではなく形式を定めているのはそのためで、
**強制力よりも、違反に気づけることを選んでいる**。

## 形式

不在を結論として述べるときは、次の4点を添える。埋められない項目は「未確認」と明記する。
**黙って省略しない。** 省略すると「確認した」と区別がつかない。この仕組みが気づかれないまま機能しなくなる経路は、これしかない。

| 項目 | 書くこと |
|---|---|
| 主張 | 何が無いと言っているのか |
| 探索範囲 | どこを、どの手段で見たか（対象・コマンド・件数） |
| 範囲の根拠 | なぜその範囲が「在りうる範囲」を覆うと言えるか |
| 反証条件 | この「無い」が誤りなら、どこを見ていなかったことになるか |

**範囲の根拠として最も安く手に入るのは一次ドキュメント。走査より先に読む。**

### 適用する場面

- 「機構が無い」「対応していない」「設定されていない」と結論するとき
- 「再現しません」「該当なし」「ログに出ていません」と報告するとき
- **他人の不在報告を受け取るとき**（人間・AI・外部ベンダを問わない）。
  調べ方が添えられていない不在報告は、そのままでは根拠にしない

## 測定を組む前に、結果を見分けられるか確かめる

> **仮説が偽だったとき、この測定はどんな出力を出すか？**

その出力が、仮説が真のときと同じなら、それは測定になっていない。組む前に気づいて止まれる。

例: `grep '^VAR='` は `VAR=`（空文字列）の行にもマッチする。
「値が設定されているか」を測りたいのに、「変数が存在するか」しか見分けていない。
しかも出力はきれいに出るので、**動いている出力を見て誤った確信を持ってしまう**。

## 「検査できなかった」を「問題なし」に畳まない

必要な状態は3つある。

```
① 検査した → 問題なし
② 検査した → 問題あり
③ 検査できなかった   ← これが抜け落ちやすい
```

畳む方向によって危険度が違う。③を②として扱えば余計な警告は出るが、危険ではない。
①として扱うと危険だ。**畳むしかないときは③を②として扱い、目立つ形で失敗させる。**

件数を数えるときも同じ。「N回中0件」のNに③が入っていれば、その0件には意味が無い。

## 合理化防止

次のように考えたら、②を飛ばしている兆候である。

| 思考 | 現実 |
|---|---|
| 「grepしたから無い」 | grepは式の範囲内に無いことしか示さない。式が正しいという根拠が別に要る |
| 「全部走査した」 | 走査した対象の集合が正しいという根拠が別に要る |
| 「丁寧に調べた」 | 丁寧さは①の質であって、②の証明ではない |
| 「N回試して0件だった」 | 検出できない構成だった可能性を消したか。Nに③が入っていないか |
| 「エラーが出ていない」 | 検査が走った証拠なのか、走らなかった証拠なのか。区別できるか |
| 「キーが無いから機構が無い」 | 定義場所を思い込んでいる。別ファイル・別階層・別名を確かめたか |
| 「ドキュメントは後で読む」 | ②の根拠として最も安く手に入る。走査より**先**に読む |
| 「ローカルで全部調べた」 | コードから分かるのは「何が起きうるか」だけ。「実際に何が起きているか」はissueやコミュニティを見ないと分からない |
| 「時間がないので裏は後で取る」 | 不在の結論は、その後の判断を確定させてしまう。裏を取る前に出すと取り消せない |
