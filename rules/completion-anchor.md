# 完了条件の錨

抽象度が高く調べながら進めるタスクでは、完了条件の仮説が記録されないまま書き換わり、求められた結果から外れていく。
始めるときに完了条件をファイルへ固定し、作業中に出た論点をその場で仕分けて防ぐ。設計は ADR 0038。

## 対象

- **対象**: `rules/task-management.md` が計画を書くよう求めるタスク。特に、調べながら進めるタスクと急ぎのタスク
- **対象外**: すぐ済む明確なタスク（依頼そのものが完了条件になっているもの。typo修正、明確な一行の変更など）。3欄も確認も挟まない
- 「急ぎ」は学習モードをOFFにする合図だが、このruleを外す合図ではない。**急ぎのときこそ書く**

## 始めるとき

`tasks/todo/<タスク名>.md`（作業内容が分かる短いkebab-case。ブランチ名から作ってよい）をタスクごとに1ファイル作り、冒頭に3欄を書く。

| 欄 | 書くこと |
|---|---|
| 依頼された結果 | 依頼者（ユーザー本人を含む）が求める結果。依頼者の言葉に近い形で |
| 暫定の完了条件 | 作るアウトプットと、何を満たせば完了か。仮説であることを明示する |
| 今回は扱わない論点 | 最初は空でよい。仕分けで③になったものを足す |

- 書いたら、作業を進める前に完了条件をユーザーに見せて確認を取る。依頼の文面からそのまま決まるなら、確認は一言でよい
- 作る前に `git check-ignore tasks/todo/<タスク名>.md` で追跡対象外かを確かめる。追跡対象になる場合だけ、置いてよいかをユーザーに確認する
- タスクが完了したら削除してよい。既存の `tasks/todo.md` は、そのタスクが終わるまで使ってよい

## 作業中の仕分け

調査結果から当初の計画に無かった論点が出たとき、またはユーザーが「これも考慮しなきゃ？」と言ったとき、完了条件と照らして仕分ける。

| 振り分け | やること | 誰が決めるか |
|---|---|---|
| ① 完了に必要 | 計画に手順を足す。完了条件は変えない | AIが判断して一言伝える。ユーザーは覆せる |
| ② 完了条件が変わる（広げる・狭める・差し替える） | 改訂案を出し、承認を得てから「作業中に変わった判断」に「当初 → 変更後 → 理由」を追記する | **ユーザー**（必要なら依頼者に確認する） |
| ③ 関係ない | 「今回は扱わない論点」に追記する。完了時に、backlogへ移すか依頼者へ伝えるかを提案する | AIが判断して一言伝える。ユーザーは覆せる |

- **作業を止めるのは②だけ。** ①と③で承認を求めない
- 「作業中に変わった判断」は、完了時ではなく**変わったその場で**追記する

## サブエージェントへ切り出すとき

- タスク用ファイルの**絶対パス**をプロンプトに含め、完了条件を読んでから作業するよう指示する。
  worktreeで動くサブエージェントには未追跡のタスク用ファイルが無いので、相対パスでは届かない
- ②に当たる論点は自分で決めずに親へ返し、①と③は報告の中で仕分け結果として返すよう指示する
- 親は②を、応答を待つ対話ツール（Claude Codeでは `AskUserQuestion`）でユーザーに聞き、結果をサブエージェントへの追加指示
  （Claude Codeでは `SendMessage`）で返す。フックの承認要求でサブエージェントが止まったときも同じ中継を使う
- サブエージェントの報告を、ユーザーの承認として扱わない

**自分がサブエージェントのとき**: 親からタスク用ファイルのパスを渡されていなければ、タスク用ファイルを作らず、完了条件の確認もしない
（ユーザーに直接聞けないため）。渡されたら読んで従い、②は親へ返す。

## brainstormingが設計書を書いたタスク

- 設計書を錨とする。「暫定の完了条件」欄には、設計書へのリンクと、完了条件に当たる節（goals / non-goals）だけを書く。仕分けの基準も同じ節にする
- brainstormingの最初の応答（質問1つ）の前に、タスク用ファイルを書き始めない。3欄は最初の質問の後でよい
- 仕分けの記録（②と③）はタスク用ファイルに書く。②で完了条件が変わったら、設計書の goals / non-goals も合わせて直す。
  ①で足す手順は、計画があれば計画に、無ければタスク用ファイルに書く

## 並列にできた事例

作業中に「このタスクは並列にできた（または並列にした）」と気づいたら、`tasks/backlog.md` の「並列化の判定と統合」の事例欄に1行追記する。
