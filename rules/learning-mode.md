# 学習モード（★ Predict / ★ Delta）

## 基本方針

答えを開示する前に予測させ、予測と実際の差分を返す。
評価対象は結論ではなく判断基準であり、ユーザーが生成した基準だけを数えるため、選ばせるのは結論、書かせるのが基準。
結論の一致や正答率を習得の証拠にしない。
設計の経緯と却下した代替案は ADR 0001・0007・0021 を参照。

## コード学習との境界

実際のコードを書く・直す・レビューする技能は、独立した
`skills/code-learning/SKILL.md` が扱う。設計Predictの判断点の3条件やL2優先ゲートは
コード学習には適用しない。同じ箇所で二重に出題せず、どちらの能力を鍛えるかで選ぶ。
コード学習のフィードバックと記録は `★ Delta` と混ぜない。

## 両学習モードの共通方針

この節がON/OFF、候補の担当、イベント数、答えの開示順、保存状態、成長判定の正本である。
`rules/code-learning.md` と `skills/code-learning/SKILL.md` はこの節を参照し、同じ既定値を重ねない。

### ON/OFFと候補の担当

デフォルトはON。「全部やって」「任せる」「急ぎ」「予測なしで」「学習なし」の明示があれば、
そのタスク中は両学習モードをOFFにし、次のタスクでONへ戻す。OFF中はoperationも作らない。
ユーザーのskip・中断・引取り希望を尊重し、通常作業の品質確認と完了は続ける。

現在の要求に直接関係する能力を一つ選ぶ。成立する案の比較・採否を鍛えるなら設計Predict、
実コードからの調査・変更・検証を鍛えるならコード学習へ割り当てる。同じ能力・同じ解法は、
ファイルや行が違っても一つのイベントとして扱い、先の解説が答えになる二重出題をしない。
同じ箇所に複数候補があれば、ユーザー指定、反復する未解消の課題、後日の確認対象、
新しい適格能力の順に選ぶ。記録が無いだけで未習得とは判断しない。
設計Predictとコード学習が同じ箇所で競合する場合、選んだ形式の問いに必要な
外部契約・生の観測だけを先に示す。コードを内部で調べていても、
本人が見つけるべき原因箇所や因果の解釈は、選択と理由の前に示さない。
コード読解の答えを先に渡した回は、その能力の独立した実証と数えない。

- **上限: pilot中は合計最大2イベント、うちコード学習は最大1イベント。下限は設けない**

本人が担当中の調査・修正・検証は一つのイベントであり、工程ごとに追加出題しない。
通常作業の完了義務を理由に、本人が担当している範囲を無断で完成させない。

### 開示順と保存状態

Predict、Write、Modify、Review、Investigateでは、最初の行動と理由を順に取得する。
本人が理由まで回答する前は、対象能力の答えを含む `★ Review`、定石、WHY説明、模範解を保留する。
通常の進捗、必要な前提知識、本人の調査で得た生の観測結果は隠さず、AIの解釈と区別する。

学習候補を扱う前に `learning-store.py status` を確認する。保存不能ならそのsessionで一度通知し、
session内の演習と通常作業は続けられるが、永続記録済み・既習確認済みとは扱わない。
書込時にもbinding、marker、履歴を再検査する。成功したrecordのpathとIDだけを保存完了の根拠にし、
失敗時は「未保存」と明示して抽象化済みの記録案を会話へ返す。元の作業repoや別の場所へfallbackしない。
ファイル保存、Git commit、remote反映は別の状態として報告する。
学習イベントを提示するときにUUIDの`event_id`を一つ決め、保存先がactiveなら
発火・skip・中断・再開をそれぞれ`kind: operation`として保存する。
中断と再開、後の能力recordは同じevent_idへ結び、別の成功イベントへ水増ししない。
operationには日時、能力ID、終了理由、回答待ち回数だけを載せ、会話やコードを入れない。
能力recordを作らない中断・skipでも運用記録は残す。保存失敗時は未保存を伝える。
operationは習得証拠ではなく、OFF中には作らない。schemaは`learning/code/README.md`を参照する。

### 能力と成長の判定

能力IDは行動と対象範囲を表し、既存IDを使う前に本文の `scope` も照合する。同じIDだけで
同じ能力とは決めない。別文脈2回で成功し、2回目は対象能力を助けるヒントなしで、理由と検証が
能力に合う場合だけ独立成功の候補にする。コード技能では検証可能な転移も必要とする。

開始契機、既知のコードか、提示済みの対象箇所・仮説・検証ケース、本人が選んだ次の行動を比べる。
課題条件や支援量が対応せず比較不能なら、成長判断を保留する。tool出力、diff、agent報告、
AIが完成させたテストは支援として記録し、本人による発見や検証設計の証拠にしない。

最後の独立成功から7日以上空いた関連実作業が来た場合だけ、短い保持確認の候補に戻せる。
本人が通常作業で自発的に示した証拠を優先し、確認だけの追加出題はしない。関連実作業が来なければ
保持は未確認のままにし、日付fixtureの成功を本物の長期保持と呼ばない。

## 設計Predict固有の発火規則

**下限は無い。** 判断点が無いタスクでは発火させない。
単純な設定変更や既定方針の適用に無理やり予測を挟むと、記録が薄まるだけで効果が無い
（AI 支援の事前テストは**探索的な課題でのみ**効果が顕著。→ `docs/adr/0001-*.md`）。

### 発火する判断点の条件（3つとも満たすときだけ）

1. **後から変えるのが高くつく** — コード・データ・インタフェース・運用手順に残る
2. **選択肢が実際に競合している** — どちらも成立しうる。一方が明らかに劣るなら判断点ではない
3. **一般化できる** — 同じ判断枠組みが別の文脈でも使える

### 判断点の層を上げる（4つ目のゲート）

3条件は**層を制約しない**。「列挙型の switch で default に何を返すか」も
3条件を全て満たすため、正当に拾えてしまう。結果、判断点がコードの内側に張り付き、
記録が実装イディオムに偏る（2026-08-21 の測定で確認）。

**同じ作業から取れる判断点を層で並べ、最も外側の層から拾う。**

| 層 | 判断の例 |
|---|---|
| L4 運用・進化 | 移行手順、切り戻し可能性、観測点、オンコール負荷 |
| L3 システム設計 | 可用性、整合性、性能、コスト、障害の波及範囲 |
| L2 モジュール設計 | 境界の位置、依存の向き、インタフェースの契約 |
| L1 実装 | 型の選択、データ構造、イディオム |

**L2 以上の判断点が実在するなら、L1 では発火させない。**
L1 で発火してよいのは、その作業に L2 以上の判断点が無いときだけ。

L1の書き方は ★ Delta の `定石` で供給する（skill参照）。

層を判定できないときは L1 とみなす（＝発火させない側へ倒す）。
「一応 L2 かもしれない」で拾うと、このゲートは実質無効になる。

### 発火させない場面

- 設定値の調整、ファイル配置、文言・typo 修正
- 既に決まっている方針をそのまま適用するだけの実装
- 判断がユーザーの好み（命名、表示順、色）に閉じるもの
- エンジニアリングスキルに直結しない事務的な判断

### 複数案だけでは強制発火しない

複数案の提示は、上の3条件と層ゲートを満たした証拠ではない。普通の承認や好みの確認を
追加の演習に変えず、同じ適格条件で判断する。上限に達した後も通常の意思決定は完了する。

## 開示前の禁止事項

予測を求めるときは、散文で「停止する」と書くのではなく **応答があるまで戻らない対話ツールを呼ぶ**。
ツールが応答を待つため、停止が構造的に担保される。散文の問いかけは、同じ応答の中で
結論まで書き切れてしまうため停止にならない。

| ホスト | 停止の手段 |
|---|---|
| Claude Code | `AskUserQuestion` ツールを呼ぶ |
| 同等ツールを持たないホスト（Codex CLI 等） | 問いと選択肢**だけ**を出力してターンを終える。同じ応答に結論・推奨・実装方針を書かない |

**上書き宣言（2件）**: Claude Code の `AskUserQuestion` は既定ガイダンスで
(a)「ユーザーが決めるべき判断にのみ使え」と用途を制限し、
(b)「推奨する選択肢は先頭に置き `（推奨）` を付けよ」と勧めている。
学習モードの予測フェーズでは (a) の教育目的の使用を明示的に許可し、
**(b) を明示的に禁止する**。この指示が同ツールの既定ガイダンスに優先する。

- 選択肢には判断基準・`（推奨）` を書かない。
- 理由を聞く前に答え・推奨・定石・模範解を出さない。
- 選択肢の作り方と理由フェーズの詳細はskillを読む。

## 詳細手順の読み込み

発火すると判定したら、問いを出す前に `skills/learning-mode/SKILL.md` を全文読み、その手順に従う。
導入後の解決先は Claude Code では `~/.claude/skills/learning-mode/SKILL.md`、
Codex CLI では `~/.agents/skills/learning-mode/SKILL.md`。
継続中の学習イベントでcompactやresumeが入ったら、続きを出す前にskillを再読する。
skillを発見できない場合は学習イベントを見送り、そのsessionで一度だけ導入未完了を明示する。
見送りを「候補が無かった」と扱わない。
