# タスク管理

1. **まず計画を立てる**: チェック可能な項目として `tasks/todo.md` に計画を書く
2. **計画を確認する**: 実装を開始する前に確認する
3. **進捗を記録する**: 完了した項目を随時マークしていく
4. **変更を説明する**: 各ステップで高レベルのサマリーを提供する
5. **結果をドキュメント化する**: `tasks/todo.md` にレビューセクションを追加する
6. **学びを記録する**: 修正を受けた後に `tasks/lessons.md` を更新する（AI側の修正パターン記録）
7. **理解を言語化する**: ★ Predict の予測と ★ Delta の差分を `learning/entries/` に記録する（ユーザー側の学びの言語化）

## `tasks/` の使い分け

| ファイル | git | 役割 |
|---|---|---|
| `todo.md` | 管理しない | **実行中の1タスク**の計画と進捗。使い捨て |
| `backlog.md` | 管理する | **まだ着手していない課題**。永続 |
| `lessons.md` | 管理する | AI側の修正パターン |

★ Predict / ★ Delta の記録は `tasks/` ではなく **`learning/`** に置く。
後日の集計と学び直しのため、1エントリ1ファイル + frontmatter の形式にしてある
（運用は `learning/README.md`）。

### `todo.md` の運用

タスクごとに使い捨てる一時ファイル。常設のテンプレートやサンプルはリポジトリに置かない。

- タスク開始時に作成し、完了後は次のタスクのために削除してよい
- 複数タスクを並行しない前提のため、常に1ファイルで足りる

### `backlog.md` の運用

境界は「今このタスクでやるか」。やるなら `todo.md`、やらないなら `backlog.md`。

- 着手したら `todo.md` へ移して展開する。完了したら `backlog.md` から消す（履歴は git に残る）
- **判断待ちの項目は「決めること」を明記する。** 作業内容だけ書くと、
  何を決めれば動き出せるのか分からなくなって放置される
- 他リポジトリの管轄なら、そちらへ移して参照だけ残す（二重管理を避ける）
