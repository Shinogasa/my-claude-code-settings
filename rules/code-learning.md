# コード学習の発火と再開

ON/OFF、候補の担当、イベント数、答えの開示順、保存状態、成長判定は、
`rules/learning-mode.md` の「両学習モードの共通方針」だけで定める。

実装・修正・リファクタリング・レビューの中で、正しさ・変更容易性・デバッグ可能性などに
実質的に影響し、別の仕事にも転用できるコード能力が見えたら、本物の作業から切り出した
小さく検証できる課題にできるか確かめる。課題にできる場合は、実装の肝心な部分を確定する前に
`skills/code-learning/SKILL.md` を全文読み、その手順に従う。

継続中の学習イベントへ返答するときも、実装や解説へ進む前に同じskillを再読し、
本人の担当範囲を確認する。「どう直せば」のように助言を求められても、明示的な引取りではない。
誤解があれば反例か観測差を一つ示し、本人の次の調査を待つ。skip、学習OFF、
「代わりに直して」という明示的な引取りは、共通方針に従う。

導入後のパスは、Claude Codeでは `~/.claude/skills/code-learning/SKILL.md`、
Codex CLIでは `~/.agents/skills/code-learning/SKILL.md`。skillが見つからない場合は
学習イベントを見送り、そのsessionで一度だけ導入未完了をユーザーへ明示して、
通常の実装・検証を続ける。見送りを「候補が無かった」と記録しない。

候補を扱う前に保存状態を確かめる。Claude Codeでは
`python3 ~/.claude/bin/learning-store.py status`、Codex CLIでは
`python3 ~/.codex/bin/learning-store.py status` を直接実行する。
`bin` はsymlinkのことがあるので、`find` の結果だけでlearning-store.pyが無いと判断しない。
statusが失敗した場合も、共通方針どおり一度だけ通知し、未保存だと明示して学習を続ける。

生成物、vendored code、lockfile、ボイラープレート、機械的変更、単純な設定・文言の変更、
検証できない好みの評価では発火しない。検査や一次資料で重要な主張を裏付けられず、
検証済みの教師routeも使えなければ、学習イベントを見送る。

設計判断の3条件とL2優先ゲートは、コード技能には流用しない。コード技能の候補は、実際のコードから
調査・変更・検証する行動が、現在の要求に直接関係するかどうかで判断する。
