# コード学習の入口

ON/OFF、候補の担当、イベント数、答えの開示順、保存状態、成長判定は
`rules/learning-mode.md` の「両学習モードの共通方針」を正本とする。

実装・修正・リファクタリング・レビューで、正しさ・変更容易性・デバッグ可能性などへ
実質的に影響し、別の仕事にも転用できるコード能力が見えたら、小さく真正で検証可能な
実課題にできるか確認する。成立した場合は本質部分を確定する前に
`skills/code-learning/SKILL.md` を全文読み、その手順に従う。

継続中の学習イベントへ返答するときも、実装や解説へ進む前に同じskillを再読し、
本人の担当範囲を確認する。「どう直せば」といった助言の求めは明示的な引取りではない。
誤解があれば反例か観測差を一つ示し、本人の次の調査を待つ。skip、学習OFF、
または「代わりに直して」という明示的な引取りは共通方針に従う。

導入後の解決先は Claude Code では `~/.claude/skills/code-learning/SKILL.md`、
Codex CLI では `~/.agents/skills/code-learning/SKILL.md`。skillを発見できない場合は
学習イベントを見送り、そのsessionで一度だけ導入未完了をユーザーへ明示して、
通常の実装・検証を続ける。見送りを「候補が無かった」と記録しない。

候補を扱う前の保存状態確認は、Claude Code では
`python3 ~/.claude/bin/learning-store.py status`、Codex CLI では
`python3 ~/.codex/bin/learning-store.py status` を直接実行する。
`bin` は symlink のことがあるため、`find` の結果だけで入口の不在を判断しない。
statusが失敗した場合も共通方針どおり一度通知し、未保存を明示して学習を続ける。

生成物、vendored code、lockfile、ボイラープレート、機械的変更、単純な設定・文言変更、
検証できない好みの評価では発火しない。検査や一次資料で重要な主張を裏付けられず、
検証済みの教師routeも使えなければ学習イベントを見送る。

設計判断の3条件とL2優先ゲートはコード技能へ流用しない。コード技能では、実コードから
調査・変更・検証する行動が、現在の要求に直接関係するかで候補を判断する。
