# 並列セッションと作業ツリーの分離

同じリポジトリで複数のエージェントが動くと、同じ作業ツリーを共有するので
ブランチが衝突する。片方がブランチを切り替えると、もう片方はチェックアウト中の
ブランチが変わったことに気づかないまま作業を続ける。

## サブエージェントを起動するとき（既定）

`Agent` ツールでサブエージェントを起動し、**そのエージェントがコミットを作る場合は
`isolation: "worktree"` を指定する。** 読み取りや調査だけのエージェントには不要。

起動するのはエージェント自身なので、ここでは検出も通知も要らない。
並列作業の大半はこの経路で起きるので、これを既定にすれば衝突のほとんどは起きなくなる。

## セッション開始時に通知を受けたとき

`hooks/detect-parallel-sessions.sh` が「別のセッションが動いている」と通知したら、
**編集を始める前に**分離する。

| ホスト | 分離の手段 |
|---|---|
| Claude Code | `EnterWorktree` ツールを呼ぶ |
| 同等ツールを持たないホスト | `git worktree add <path> -b <branch>` を実行し、以降そのパスで作業する |

通知が届くのは後から起動した側だけ。先に動いているセッションは作業中で
中断のコストが高いので、**通知を受けた側が移動する**。

読み取りや調査だけで終わるセッションなら分離は不要。ただし途中で編集を始めることになったら、
その時点で分離を検討する（通知はセッション開始時にしか出ない）。

## 分離した後にやること

`git worktree` は**追跡されていないファイルを持ってこない**。
次のものは新しい作業ツリーに無いので、必要なものを復元する。

- サブモジュール → `git submodule update --init --recursive`
- `.env` などのgitignoreされた設定ファイル → 元の作業ツリーからコピー
- 依存パッケージ・仮想環境・ビルドキャッシュ → 各エコシステムの手順で作り直す
- 会話履歴と永続メモリ（`~/.claude/projects/<作業ディレクトリ由来の名前>/`）は
  作業ディレクトリごとに分かれる。worktreeでは**メモリが空の状態から始まる**

## worktreeでは解決しないこと

worktreeは**ファイルシステムを分けるだけで、実行環境は分けない**。
次のものはリポジトリの外にある共有資源なので、分離しても衝突は続く。

- 開発サーバのポート
- ローカルDB（別ブランチのマイグレーションが互いに干渉する）
- コンテナ名・ボリューム名

これらは並列作業そのものの制約であり、worktreeを使うかどうかとは別に扱う。

## エージェント設定リポジトリ（範囲を限って使う）

**エージェント設定リポジトリでは、動作中の設定に効くパスを触る作業だけを本体で行う。**
それ以外の作業（テスト、ADR、仕様書、backlogなど）はworktreeで行ってよい（ADR 0031）。

`~/.claude/` などは、絶対パスのシンボリックリンクで本体の作業ツリーを指している。
そのため、worktree側で `rules/` や `hooks/` を編集しても、動作中のエージェントには反映されない。
一方で、本体でブランチを切り替えると、並列で動いているセッションが読む規約まで入れ替わる。

### 本体で作業するパス

`setup.sh` がシンボリックリンクを張る元のパス。**正本は `setup.sh` のリンク定義（`add_link_target`）**で、
次は2026-10-09時点の写しである。

- `CLAUDE.md`、`rules/`、`hooks/`、`agents/`、`commands/`、`output-styles/`、`bin/`、`statusline.js`、`skills/<各skill>`
- `codex/` のうちリンクするもの（`RTK.md`、`MODEL_ROUTING.md`、`hooks.json`、`agents/`）
- サブモジュール `claude-code-best-practice`、`codex-cli-best-practice`

`settings.json.template`、`env.json.template`、`setup.sh` 自体は、`setup.sh` を実行して初めて効く。
編集はworktreeでよい。マージ後に本体で `setup.sh` を実行する。

### 作業の流れ

1. **作業を始める前に、触る予定のパスを上の一覧と照合し、本体とworktreeのどちらで作業するかをユーザーに確認する。**
   途中で一覧のパスを触る必要が出たら、確認し直す。本体へ移るときは、pushしてから移る
2. worktreeは `.claude/worktrees/` に作る。一時ディレクトリなど、リポジトリの外には作らない。
   開始時にサブモジュールを初期化する。永続メモリは空から始まる
3. 本体でブランチを切る前に `bin/detect-parallel-sessions` を実行する。
   並列セッションがいれば、待つ・worktreeに回す・構わず進めるのどれにするかをユーザーに聞く
4. 終わったら、本体を `main` に戻す

この節は、上の「サブエージェントを起動するとき」の既定（`isolation: "worktree"`）より優先する。

### 仕組みで止めていること

- `setup.sh` は、worktreeで実行されると何も変更せずに止まる。リンク先がworktreeへ移り、
  そのworktreeを消した時点ですべてのリンクが切れるため
- `.githooks/pre-commit` は、worktreeに `patterns-local.txt` が無ければ本体の作業ツリーの定義を読む

`hooks/detect-parallel-sessions.sh` はこのリポジトリを自動で除外するので、
通知そのものが出ない。**通知が無くても安全とは限らない。** 並列セッションの有無は自分で確かめる。

### 本体で作業するときに衝突を避ける

本体の作業ツリーは並列セッションと共有している。

- **並列セッションがいる間は、ブランチを切り替えない・作らない。** 切り替えると、
  もう片方のチェックアウト中のブランチと、読んでいる規約まで変わる
- **今チェックアウトされているブランチと無関係な変更をコミットしない。**
  無関係なコミットが相手のブランチ（そのままPRになる）に入り込み、
  後から履歴を書き換えないと取り除けなくなる
- 無関係な変更があるときは**コミットせずに保留し**、相手のセッションが
  終わってからコミットする。判断がつかなければユーザーに確認する
  （`git stash` も共有の作業ツリーを書き換えるので、退避にはならない）
